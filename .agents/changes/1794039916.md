# The demo's maximal screens

> Change `1794039916` — 2026-11-07

## Goal

Tags overlapped and sat awkwardly in a plugin's views, and the demo could not show it. It had no tags at all in a list
beside a preview, three at most in a metadata row, and none after a link or a secret: every screen showed a variation
with nothing in its way. Seeing the failure took the data of the plugin that found it. Tags are dock2's own component, a
plugin only names them, so the demo can reach every one of these failures with made-up data.

## Implementation

A sixth kind, Maximal, in `Plugins/demo/src/maximal.rs`, with a Demo Maximal command. No renderer changed: this makes
failures visible and fixes none of them.

A kind rather than more rows on Every Row, so the two kinds of screen stay readable. A variety screen is meant to look
right and shows each variation alone; a maximal screen fills a view past its room, so something failing there is the
point. Filling Every Row would have made it hard to tell one from the other.

The table in `sections()` draws both `max.rows` and `max.preview`, so a row can be compared wide and compact, and each
row beside a preview repeats its own tags as a metadata row. `max.preview` is the kind's first, since a compact row has
the least room and shows the most on one screen. `max.detail`, `max.form` and `max.grid` take the same approach to the
rest of the view kinds.

## Observations

Seen in a Tart VM on macOS 27.2, a debug build, in both appearances. Each is in the renderer and none is fixed.

**Rows.** `RowsView.show` sets the title's end from a fixed gutter (`trailing`), never from what stands at the row's
end, while `layoutTrailing` places that end independently:

- The tags draw over the title and subtitle. A compact row with no accessory text keeps only the ×'s room. A wide row
  keeps 150 pt, which four tags exceed.
- Accessory text beside tags moves left of them, and over a long title, for the same reason.
- A strip wider than the row runs past the pane's leading edge, under the title, clipped by the pane.
- The strip is one image, shown at its own size only if it is over 16 pt tall and wider than tall. Otherwise it is
  fitted to 16 × 16: a tag narrower than it is tall shrinks, an empty one is an oval, and a strip of symbols alone, whose
  size is `size * 0.6`, shows as specks.
- A symbol composited into the strip loses its template rendering, so an untinted one is black in either appearance, on
  the dark ground too.
- An accessory naming a tag and an icon draws the tag and drops the icon.
- In a list wide enough for a hint, the selected row draws ↩ in its tags' place.

**Metadata.** `DetailComponent.body` lays tags out as attachments in the text:

- Wrapped lines have no gap: 18 pt pills on an 18 pt pitch, measured as 36 px on 36 px at 2×.
- Between tags is a space in the row's font, 3 to 3.5 pt, against 6 pt between the same tags in a row (`AccessoryImages`).
- That space takes the row's attributes, so after a link it is underlined.
- A tag wider than the pane runs to the pane's edge and is clipped there. Nothing truncates it.

**Both.** A newline in a tag draws two lines in an 18 pt pill, clipped above and below. Yellow text on its own 16% fill
reads poorly in the light appearance.

**Elsewhere.** A detail's buttons are centred, so too many are clipped at both ends, the first among them, though ⌘K
still reaches them. The scrubber's labels are 48 pt wide and clip without an ellipsis. A form's field titles clip without
one too. A grid cell's insets are fixed: at twelve columns a picture is about 5 pt, by twenty it is gone and AppKit logs
that a constraint "exceeds internal limits", and at one column the title is below the fold.

What is left to design is what gives way when tags outgrow their room: the title, the tags, or a count of those left
out. The title's end has to come from the row's real trailing content whichever it is.

Not covered: search results and tiles, which the demo does not draw and which have no tags; a preview list that is also
loading, empty or filtered by its owner. The Swift tests were not run, since only the demo's Rust and manifest changed.
