# Remembering Open With's app

> Change `1792645924` — 2026-10-21

## Goal

Open With listed Finder's apps but could not change which one a file opens with. Finder does that in Get Info
("Change All…") and, under ⌥, "Always Open With" for one file. The user ruled out opening Get Info: a Finder
window full of unrelated facts that window managers handle badly, which is much of what dock2 is for. They
proposed pills under Open With's apps — "Remember for (this file) (this extension)" — chosen before the app,
and asked for the arrows and ↩ to reach them, with the mouse alone acceptable if that failed.

## Implementation

**What macOS allows, measured.** `NSWorkspace.setDefaultApplication(at:toOpenFileAt:)` keeps an app on one
file, silently, in the `com.apple.LaunchServices.OpenWith` extended attribute; it needs write access.
`setDefaultApplication(at:toOpenContentTypeOfFileAt:)` sets it for the type, and on macOS 27 the system asks
first for every type tried, a made-up extension and `.txt` alike: an alert from `CoreServicesUIAgent`, at
window level 8, carrying Finder's icon, naming the extensions ("“.txt” and “.text”") and both apps. The call
waits for the answer. A refusal comes back as `NSCocoaErrorDomain` 256, "The file couldn't be opened" — the
code a real failure has — so `OpenWith.remember` reads the type's default back and compares bundle
identifiers rather than reading the error. dock2 asks no question of its own: the system's states the scope
better than dock2 could.

**A file's own app outranks its type's**, so All .ext would seem to fail on the very file it was chosen
from if that file carried Finder's per-file choice. A yes removes the attribute from the files picked. No API
does it; removing the attribute works, but a URL LaunchServices has already answered for keeps the old answer
until `removeAllCachedResourceValues()`. "(this file)" is likewise read from the attribute's presence:
comparing the file's default with its type's disagreed on 2 of 1,500 files here, one of them without any
attribute (a `.ram` file LaunchServices sends to QuickTime though IINA has the type).

**Scopes.** This File (These Files) needs write access to all of them; All .ext a single content type and a
single extension among them, never none — an extensionless file is `public.data` or as broad, and a choice
made from one file should not move that. Folders get neither. Picking with a pill lit dismisses first, then
remembers, then opens, so macOS's alert is not under the app's new window. A refusal still opens the files in
the app picked, once.

**The row.** NSMenu's own palette (`presentationStyle = .palette`, macOS 14) was tried first: given text-only
items it draws a checkmark blob with no titles, and ↩ on it picks the item and closes the menu. A custom view
row (`MenuPills`) keeps the menu open on a click, but an event monitor sees no keys while a menu tracks.
Making the row the menu window's first responder while it is highlighted does: `keyDown` arrives, and what
the row passes to `super` reaches the menu, so ↑ ↓ leave the row and ← past the first pill closes the
submenu. `acceptsFirstResponder` is true only while highlighted, or the window hands the row the keys as it
opens. `NSApp.currentEvent` is a key-down when the arrows move the highlight, so only the keyboard rings a
pill. `MenuBuilder` routes `menu(_:willHighlight:)` to the row.

**Search.** Search's ⌘K Open With now builds the same submenu (`ResultAction.submenu`); its pushed list in
"Show all…" keeps `children`, with no room for pills.

## Observations

Seen live in a `DOCK2_DEBUG` build, keys posted through `dock2 debug key`, menus captured by window:

- Files' ⌘K → Open With on a `.txt`: TextEdit (default), the rest, then the row, its label in line with
  the apps' icons. ↓ reached it with This File ringed; → and ↩ lit All .txt; ← and space moved the light to
  This File; ↑ went to Zed, the ring gone and the light kept.
- ↩ on Zed with This File lit: no prompt, the attribute written, the file's default Zed. Reopened, the menu
  listed "Zed (this file)".
- All .txt with TextEdit, already the type's default: no prompt, the attribute gone, the file back on
  TextEdit.
- All .txt with Zed: dock2 dismissed and macOS asked "Do you want all documents with the extensions “.txt”
  and “.text” to open with “Zed”, or to keep using “TextEdit”?" Kept: plain text stayed on TextEdit, and
  the file opened in Zed once the alert closed.

Not seen: a click on a pill in dock2 itself (a posted click in a harness toggled it and kept the menu open);
the pills in search's ⌘K menu; VoiceOver on the pills' radio buttons; a file in iCloud only.
