# Badges and minimised windows

> Change `1792656711` — 2026-10-22

## Goal

The dock showed nothing of an app's badge, and nothing of a minimised window: the window went into the hidden
system Dock and dock2 drew no sign of it. Both are part of the system Dock that dock2 replaces.

## Implementation

**Measured first**, on this Mac's Dock in the dark appearance, through Accessibility and screenshots, with a
test app that badges itself and minimises its own windows on command. The Dock was auto-hidden, and synthetic
moves do not reveal it, so `com.apple.dock` was exported, auto-hide turned off for the photographs and back on,
and the domain diffed against the export afterwards (tile size had been rewritten as an integer, and was put
back as a real).

- **The badge** is `tile × 25/64` across: 50pt at tile size 128, 25 at 64, its top right exactly on the icon
  square's. "4" and "12" are circles; "1234" is 72 wide and "New" 65, both 16pt more than the label's advance
  at 25pt — the regular system font, at half the badge's height, its capitals centred. The red reads sRGB
  (246, 68, 58) at its middle, a shade darker at its top. A shadow darkens about 5pt below and 4pt beside it.
  dock2's badge, drawn from these, lands on the same device pixels for "8", "4" and "1234"; its shadow profile
  is within five levels of the Dock's, and a lone digit sits one point left of the Dock's.
- **The minimised window** is a tile of the app tiles' width, after a separator, before the Trash, in the
  order minimised. At tile size 128 an 870 × 946 window was drawn 110.75 × 120, centred on the icon square
  within a point — 15/16 of the tile, aspect kept — and the app's icon 3/8 of the tile in the corner. Its menu
  is one item, Open “title”. An app's own menu lists its windows first, ◆ on a minimised one and ✓ on the main
  one, and only if the app has a Window menu.
- `AXStatusLabel` is absent for no badge, the text for any other — a space for `badgeLabel = " "`, which the
  Dock draws as a bare dot; `""` sets none. The Dock posts no notification when it changes (ping found the
  same), so it is polled. A read of every item costs 0.2 ms; it runs off the main thread every second while
  the dock is on screen, and immediately as the dock starts to show, which beats the slide.
- **A Dock restart clears every badge and brings every minimised window back.** A badge returns only when its
  app sets a different value, since AppKit skips a label equal to the last. dock2's takeover restarts the Dock
  at launch and quit, so this comes with it, as it would with `killall Dock`.

**Minimised windows are read off the system Dock.** A first build watched windows instead — an `AXObserver`
per app, hearing each minimised and restored — and drew a tile per window it heard minimised. A group of tabs
broke it: AppKit posts `AXWindowMiniaturized` for every tab and every tab reads `AXMinimized`, so three tabs
made three tiles where the Dock makes one item. Measured with a test app (a group of two tabs, one of three,
two windows of one title):

- Each item is an `AXMinimizedWindowDockItem` in the Dock's list, in the Dock's order, with `AXTitle` and the
  actions Press and Show Menu, and nothing else: no URL, no app, no window number; `_AXUIElementGetWindow`
  on one gives the Dock's own window, and twenty undocumented attribute names were refused.
- The Dock posts `AXCreated` and `AXUIElementDestroyed` on its application element as items come and go —
  unlike a badge — so `SystemDockItems` (which replaces the badge reader) observes it on a thread of its own
  and reads every item again on each. A read at launch can find no Dock, since dock2's takeover has just
  quit it; a Dock missing is looked for every half a second for ten, and a Dock's exit is watched.
- Pressing an item restores its window and brings its app forward (Finder to the test app), with the Dock
  hidden: the Dock's own click, which replaces the tile's Accessibility raise.
- The item keeps the title from the moment of minimising: after a retitle the app says the new one and the
  Dock the old.

An item still needs its app, for the icon in the corner, and its window's size, for the shape. Only the title
links the two, so `MinimisedWindowMatch` takes, once per item, the minimised window of that title no other item
has that was minimised last. In all three runs a group of tabs said its hidden tabs were minimised first and
the tab on show last, so the match takes the tab on show. The Dock showed an item 0.5 s before the app's
notification when minimised through `AXMinimized`, so an unmatched item is matched at the next change. A
wrong match draws the wrong shape or icon, nothing worse: the count, order, title and click are the Dock's.
`AppWindows` stays for the apps' menus.

**"Minimize windows into application icon" became part of the system Dock's takeover.** With the user's
`minimize-to-application` on, a real app's minimised window has no item (measured with Finder), so dock2
would have nothing to draw with its own setting off. The takeover writes it false with the other keys; the
user's value is journaled and given back. A journal an older dock2 wrote lacks the key, and the Dock then
still holds the user's value, so `engage` completes the entry before writing. Run against the live Dock:
the user's `true` was journaled, the hidden Dock read 0 and drew the tile, and quit, `kill -9` (the guard) and
a hand-written older journal each put `true` back; `com.apple.dock` was exported first and matched it after.

**Thumbnails were left out.** ScreenCaptureKit does list minimised windows (`onScreenWindowsOnly: false`) and
`SCScreenshotManager` captures them — four of four, their contents current, tab bar and all, about 25 ms
each — with Screen Recording. It was declined for another permission prompt, and the Dock's tile is drawn
around a blank window as before; menus and badges need only Accessibility.

A minimised window's AX subrole reads `AXDialog`, not `AXStandardWindow`, so a window is kept if it is
standard or minimised. The first build trapped: a timer handler written in a main-actor method was taken to be
the main actor's and checked at run time on the badge queue. Off-main closures are `@Sendable`.

## Observations

- The genie still targets the hidden system Dock's tile, not dock2's: nothing public moves it.
- Measured in the dark appearance only. The badge's red may differ in the light one; the blank window follows
  the dock's appearance, where the Dock shows the window as it is.
- A label wider than the icon is truncated at the icon's width: dock2's limit, not measured.
- Only one window shape — portrait — was measured: this Mac tiles new windows, so the test app could not hold a
  landscape one. A landscape window is fitted to the same 15/16 square, unverified.
- Windows on another Space when dock2 starts are not in `kAXWindows`, so they are missing from their app's
  menu until they change; minimised ones are always listed. A group of tabs lists each tab as minimised in
  the menu, as the Window menu does.
- The tab on show being minimised last was seen in a test app's groups only, not Safari's, Finder's or a
  terminal's. Two windows of one title already minimised when dock2 starts — after a crash, when the Dock is
  not restarted — may take each other's shapes.
- An app with no Dock tile of its own gets an item even under "Minimize windows into application icon"; dock2
  hides it with its own setting on, as it hides the rest.
- Badges were tested with a test app's `NSDockTile` badge, not a real notification's; an app's progress
  (`AXProgressValue`) is still unread.
- Without Accessibility neither shows; that path is code-read, not run, since this session's terminal holds
  the grant the debug build inherits.
