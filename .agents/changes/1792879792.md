# Request Access beside every pane

> Change `1792879792` — 2026-10-24

## Goal

Change 1792878482 gave each prompted permission one button: Request Access… while macOS had not asked, Open
System Settings… after. That hid the request on the row that most needed one. After its first permission check
Accessibility always reads as off, so it only ever showed the pane, and Paste from Other Apps never got a
request at all. A request and the pane are two different things to do, and every permission should offer both.

## Implementation

Every permission macOS has a prompt for shows Request Access… and Open System Settings… side by side. Request
is disabled when macOS would not prompt, and a caption then says macOS has asked already and Dock2 is listed in
System Settings. `PromptedPermission` gains Paste from Other Apps, an answer for "asks at each read", and
`prompts(at:)`. `FileAccess`'s pasteboard pane moved into it, so clipboard history's paused notice uses it too.

The three permissions do not prompt alike:

- **Accessibility** prompts again while it is off: Request stays enabled until it is allowed.
- **Screen Recording** prompts only while TCC's preflight says it was never asked.
- **Paste from Other Apps**: the header says an app that has never raised the paste alert reports `.default`
  and is not listed in the pane, and the first programmatic read raises the alert, changes it to `.ask` and
  lists it. Request reads the first item on the pasteboard, off the main thread in case the read waits on the
  alert. A fresh probe on this Mac reported `.alwaysAllow` before any read, read without an alert, and never
  reached `.default`. The `.default` path is the header's, unseen.

Full Disk Access has no Request: macOS has no prompt for it, so the button would do nothing. TCC's preflight
reads off for it even with no row, so there is no "not asked" state to show either. A probe's first refused
listing of `~/Library/Safari` created its row, and dock2's own Full Disk Access check is that listing, so
dock2 is already in the pane by the time Settings opens. The footer now says so. The three folders keep their
choice button: in that mode dock2 opens them, which is itself the request, and a folder's prompt comes once.

## Observations

- Seen in the installed build of 1792878482: the Screen Recording request at 14:59:53 (`preflight=no`), dock2
  listed, switched on at 14:59:58, relaunched at 15:00:03. This change's layout has not been seen: it was not
  installed.
- A stale grant: after a reinstall, the Full Disk Access row stays on for the old build's cdhash. tccd answers
  denied (`Failed to match existing code requirement`). Dock2 then reads "Not allowed" while System Settings
  shows it on. Nothing dock2 can request fixes that. Turning it off and on again in the pane should store the
  new build's requirement; untested. Accessibility and Screen Recording rows were rewritten for the new build
  instead.
- With Full Disk Access stale, launching the reinstalled build raised the Desktop, Documents and Downloads
  prompts at once (14:59:29–32), in the queue ahead of anything else.
- Accessibility's prompt did not reappear for a second request 35 s after the first. Request may look dead
  for a while after a prompt.
- An empty pasteboard gives Paste from Other Apps' request nothing to read, so nothing appears.
