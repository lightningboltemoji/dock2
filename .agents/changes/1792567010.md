# Files' right-click menu

> Change `1792567010` — 2026-10-21

## Goal

Files had no right-click menu. The user asked for one with Open, Open With ("can we pull from Finder?"),
Move to Trash, Rename, Copy Path and a new Copy Contents. Copy Contents should ask first, inline and not in a
window, past 10 MB, since a file that big on the clipboard is likely a mistake. Files' ⌘K menu already held
most of these, and the user agreed the two should be one menu.

## Implementation

**One menu.** `showActions` became `actions(for:in:)`, which builds the menu for a list of items and a
folder. ⌘K passes the selection and pops the menu beside it. A right-click passes what it was on. The actions
it called read `selection` or `state.tab.focus` (`trash()`, `copySelection()`, `openSelection()`,
`newFolder()`, `rename` in the focused column, ⌘K's Open going through `key(.open)`, which first accepted any
banner question). They now take their items, and rename and a folder's Open find the column by the item's
parent folder (`column(holding:)`).

**What a right-click acts on.** If the clicked item is selected, the menu is for the selection. Otherwise it is
for that item alone and the selection is left as it was. This is the table convention, and it keeps a
right-clicked folder from opening a column and moving the strip. Selecting on right-click was the
alternative. Finder's column view was not checked for which of the two it does. Between items, the menu is
for the column's folder.

**The ring.** First built through the table's own handling (set `menu`, call `super.menu(for:)`), the clicked
row got a square-cornered box across the column's full width, unlike the selection's inset rounded band.
`ColumnTable` now returns the menu itself, makes `willOpenMenu` a no-op so the table draws nothing, and
`SelectionRowView` strokes a 2 pt accent ring on the band's rect. The ring shows only when the menu is for the
row alone: a selected row's band already says it is the target.

**Ask Siri.** macOS 27 put "Ask Siri" at the top of the right-click menu, highlighted. `MenuBuilder` turns
`allowsContextMenuPlugIns` off for every dock2 menu, and it went. The dock's tile menus were not looked at
before or after.

**Open With** (`OpenWith`, Dock2System) is the LaunchServices list Finder uses: `urlForApplication(toOpen:)`
first, marked "(default)", then `urlsForApplications(toOpen:)` sorted by name. For several items it is the
apps that open them all. Each app appears once by bundle identifier, the first copy LaunchServices lists
winning, because this Mac lists Fiber four times (installed plus three dev builds). Search's Open With used a
`prefix(12)` of the raw list and now uses the same helper. Finder's "Other…" was left out: it is an open
panel, a window.

**Copy Contents** (`FileContents`, Dock2System) is for one file that is text or an image macOS reads:

- **Images** are the types in `CGImageSourceCopyTypeIdentifiers`. They are copied as their own bytes under
  their type plus a PNG (`CGImageDestinationAddImageFromSource`, which keeps the orientation) for apps that
  take nothing else.
- **Text by type** is anything conforming to `public.text`, except rich text, whose markup is not what
  copying its contents means.
- **Text by content** covers the rest. Measured on this Mac: `.gitignore` is `public.data`, `.env` a dynamic
  type, and `.ts` `public.mpeg-2-transport-stream`. So any other local file is judged by its first 8 KB:
  UTF-8 with no NUL, allowing a character cut off at the 8 KB mark.
- **A file only in iCloud** is judged by type alone, since reading it would download it.
- **SVG** has no CGImageSource type, so it copies as its source.
- **Decoding** is UTF-16 by its byte order mark and UTF-8 with the mark dropped. Anything else throws
  `fileReadInapplicableStringEncoding`, which goes on the row as any operation's failure does.

The read is off the main thread. Over `askAbove` (10,000,000 bytes, so "10 MB" means what the preview's
`ByteCountFormatter` shows), it asks first through the panel's confirmation: "“big.log” is 12 MB." with
Cancel and Copy Contents, not red. It was first a row in Files' banner, the conflict question's shape, since
the confirmation was then a red pill for destructive actions that took no clicks. The user disliked the row,
which pushed the columns down as it came and went. The confirmation became a glass toast with buttons
instead (`1792567577`), and the question moved there.

**Verified.** `FileContentsTests` cover judging by type, by content and by cloud; the 8 KB cut; UTF-8, its
mark and UTF-16; an undecodable file; an image's representations; the pasteboard; and Open With's order and
uniqueness against this Mac's apps. Live, with `DOCK2_DEBUG=1` and the user's hands off:

- `notes.txt` right-clicked unselected: ringed, the selection unchanged, and Copy Contents put
  "hello from notes\n" on the clipboard.
- `big.log` (12 MB): it asked first, and ↩ copied 12,000,000 bytes. That was the banner's row; the toast that
  replaced it was seen in `1792567577`.
- `image.png`: the clipboard held its 27,660-byte PNG.
- Open With on the PNG: Preview (default), a separator, then ColorSync Utility through Safari, with icons and
  Fiber once.
- `probe`, a folder in a column without the keys: no Open With or Copy Contents. Rename edited it in that
  column, and Esc kept the name.
- Between rows: New Folder and Open in Finder.

## Observations

- With the banner's row up, the strip showed one more column on the left than before, and came back after.
  The conflict question still raises it.
- Open on a folder from the menu, Open With for several files, and the menu on search's results were not
  driven live.
- No Copy Contents for several files, rich text, PDFs or other binaries. Concatenating several text files is
  the obvious next one if wanted.
- Finder's Quick Actions and Services are not offered. AppKit could add Services to the menu if the table
  vended file URLs as a services requestor.
- Saving captures into the folder being shown relisted it and moved the columns between runs. A driven
  run's captures belong outside it.
