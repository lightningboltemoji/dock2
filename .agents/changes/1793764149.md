# What a grant holds open ends with it

> Change `1793764149` — 2026-11-03

## Goal

Revoking `now-playing` in Settings left the plugin seeing what played. `setGranted` wrote the choice and
stopped nothing, the observer's `send` checked only that the plugin was on, and `unloadIdle` counted the
subscription as busy, so the plugin kept hearing every track until it was switched off or dock2 quit. The
same was true of any answer in flight: a request made under `network` still answered after `network` went.
The first step of the capabilities plan (`design/plugins.md`).

## Implementation

`PluginResources` holds everything the host keeps open for a plugin, each under a key (`timer`, `request`,
`subscription`, and the kinds the later steps add) and the capability that allowed it: nil for a timer or a
derivation, which need none. It replaces the host's three tables: `timers`, `subscriptions` and `inFlight`.

- **Revoking** goes through the host (`setGranted`, `setResults`), which writes the choice and ends what the
  capability holds. A request ended this way hears `error(request, "<capability> was revoked")`, so a plugin
  showing "loading" can stop. A subscription or a stream just stops: the plugin is told what it holds by the
  `granted` event of the next step.
- **Answers** come back through `answer`, which delivers one only while its request is still held and lets
  it go as it does. A cancelled `URLSession` task's completion, a Keychain read that finishes after a revoke,
  or a derivation that finishes after a stop, all arrive to nothing.
- **Idle** is "nothing held" plus a tile or a view, as before.
- **The subscription** is held before `NowPlaying.observe` is called, since the current state is delivered
  synchronously as the observation starts. It is held again with the observation's `end` once there is one.

Settings' `PluginsModel` no longer writes grants itself: a switch that only wrote the file was the bug.

## Observations

- A capability revoked in the config file, by an editor or another Mac, already restarted the plugin
  (`onChoicesChanged`), which ends everything. Only Settings' switches stopped nothing.
- A timer's event handler checks that it is still held, so a cancel that races the main queue's delivery is
  never heard.
- Tested in `PluginResourcesTests` and in the host: the subscription ends, the instance then unloads, and an
  HTTP request cancelled by its revoke is told so and its answer never arrives.
