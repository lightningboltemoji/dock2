# The engine: plugins as native code, in MAP_JIT memory

> Change `1794536247` — 2026-11-12

## Goal

Pulley, wasmtime's interpreter, ran plugins 50–80× slower than native code. A plugin answering with a
1.4 MB view (5,000 rows: a title, a subtitle, keywords, an accessory and two actions each) took 158 ms to
build and serialize it, three times the 50 ms interactive budget, against 2 ms in native Rust and 7 ms from
Cranelift. Pulley was chosen to need no executable memory, and so no entitlement. That reason was weaker than
it looked: entitlements are part of the signature, and an ad-hoc one carries them with no certificate, so
`make install` and CI's builds can carry them as well as a Developer ID build.

## Implementation

**Which entitlement.** Tested with one binary signed five ways on macOS 27.2.1 with SIP on:

| Signature | wasmtime's own loading | code in MAP_JIT memory |
| --- | --- | --- |
| ad-hoc, no hardened runtime (`make install`) | runs | runs |
| hardened runtime, no entitlements | SIGKILL as code first runs | `mmap(MAP_JIT)` EINVAL |
| + `allow-jit` | SIGKILL | runs |
| + `allow-jit`, `jit-write-allowlist` | — | runs, through the listed callback |
| + `allow-unsigned-executable-memory` | runs | runs |

wasmtime maps code read-write, then `mprotect`s it executable. Only `allow-unsigned-executable-memory`
permits that, and it lets anything in the process make any memory executable. `allow-jit` permits only
MAP_JIT memory, where on Apple Silicon each thread sees the memory writable or executable, never both.
wasmtime 49 can be pointed at such memory. `Engine::precompile_module` compiles without loading;
`Module::deserialize_raw` loads from memory the embedder owns, with no protection change of its own and no
write to the code (the image carries no relocations); and `Config::with_custom_code_memory` puts the publish
step in the embedder's hands. `Engine/src/jit.rs` maps a region with `MAP_JIT`, copies the image in, flushes
the instruction cache and hands the region to `deserialize_raw`. Its publish hook only checks that the code
lies in such a region, so a module loaded any other way fails with an error instead of a kill. Compiling and
reading back from the cache now take the same path. A `DwModule` and every `DwInstance` hold the region
behind an `Arc`, declared after what runs it, so it is unmapped only after the last module or store goes.
wasmtime's global code registry is let go in the same drop.

**The allowlist.** `com.apple.security.cs.jit-write-allowlist` disables `pthread_jit_write_protect_np` for the
whole process and lets `pthread_jit_write_with_callback_np` run only callbacks listed in the image's
`__DATA_CONST,__pth_jit_func` section. `write_image` is the only one listed: a `#[used]` static in Rust,
standing in for C's `PTHREAD_JIT_WRITE_ALLOW_CALLBACKS_NP`. Its argument can be forged, since any code can call
it, so it writes only to the region the loader left pending, once. The section survives both links: in
`Dock2.app`'s executable it rebases to `dockwasm::jit::write_image`.

The real `libdockwasm.a`, linked into a C program and signed four ways on this Mac:

| Signature | Plugin suite | Write toggle | Unlisted callback |
| --- | --- | --- | --- |
| ad-hoc + both entitlements (`make install`, CI) | passes | SIGKILL | SIGKILL |
| hardened + both (as Developer ID) | passes | SIGKILL | SIGKILL |
| hardened, none | "no memory for native code: Invalid argument" | | |
| ad-hoc, none (`swift build`, `swift test`) | passes | open | runs |

The suite covered compiling, reading back, `started`, a call through `log`, a spin stopped at 50.5 ms, a
hoard stopped at the cap, a panic as a trap, and 200 compile, start and free cycles. The allowlist holds
without the hardened runtime too. So `Resources/dock2.entitlements` goes on both of `make app`'s signing
paths, and a build from source runs plugins the way a release does. Without the entitlement,
`pthread_jit_write_with_callback_np` toggles protection around the callback itself, so tests and debug runs
need nothing.

**Nothing else in the process writes JIT memory.** A `JSContext` running a hot loop survived every signature.
dock2 imports neither WebKit nor JavaScriptCore; `QLPreviewView` is the one host of other code.

**Numbers**, release builds on this Mac:

| | Pulley | native |
| --- | --- | --- |
| 1.4 MB view, plugin at `opt-level = "s"` | 158 ms | 7.7 ms |
| the same, plugin at `opt-level = 3` | 90 ms | 4.0 ms |
| Bitwarden, 3,001 items with an organization | 13 events, longest 228 ms | 13 events: the sync and the keys 18 ms, then 3–6 each |
| 600,000 PBKDF2 rounds inside a plugin | 5.6 s | 0.3 s |
| compiling the test guest | 17 ms | 26 ms |
| reading it back from the cache | 0.06 ms | about 1 ms: a 1.1 MB copy, the mapping and its unmapping |

The engine stays at `opt-level = "s"` throughout. Raising wasmtime and Cranelift to `-O3` saved 4 ms of
compiling and 0.4 ms of reading back, both cached or once per instance, and changed no call. The per-crate
`-O3` that Pulley needed is gone with it. The version string names the architecture
(`wasmtime 49.0.4, aarch64`), so every cached module's key changes; the first start compiles once and
`removeCompiled` drops the Pulley files.

**Rejected.** `allow-unsigned-executable-memory`: it works with wasmtime as it comes, but it weakens the whole
process. Keeping Pulley beside the JIT as a fallback: a second engine to test, for a failure that only a
signature without the entitlement causes, and that one fails loudly at compile. Precompiling to signed dylibs:
plugins are installed by users, after dock2 is signed.

## Observations

- Seen in Tart VMs on macOS 26.6.2 and 27.2: each signature of `Dock2.app` ran the Test Guest's command, the
  demo gallery and its two thousand rows; the first start compiled and the next read back. The old Pulley
  `demo` file was replaced. But neither VM enforces code signing (`OBSERVING.md`), so enforcement was seen
  on this Mac alone, and in a command-line program rather than in the app.
- No Developer ID build has been notarized, so the notary service has not been seen accepting
  `jit-write-allowlist`. `allow-jit` is one of the hardened runtime's standard exceptions.
- The callback's check is dock2's own. Code that can already write dock2's memory could set `PENDING` and
  call it. The allowlist narrows the way into executable memory to one function; it does not close it.
- Nothing in `make test` signs a binary, so a stripped allowlist section or a wasmtime path around the hook
  would go unnoticed until the app ran. A check — the C program above, signed with the entitlements — could
  run in CI if its runners enforce code signing; unknown.
- On macOS 27, a bundle run from `/tmp` logs `sandbox_extension_issue_file_to_process failed` with or without
  the entitlements; not compared against `main`.
- Plugins are built at `opt-level = "s"`, and "3" halves the 1.4 MB call. dock2 decoding that answer takes
  36 ms (`PluginInstance.decode` parses it, writes each effect back out, then decodes it), outside the budget
  but before the user sees it, and now nine tenths of the wait. Both are separate changes.
