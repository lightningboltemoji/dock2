# Icons among apps

> Change `1792874623` — 2026-10-24

## Goal

Search drew dock2's own results — Settings, Quit, Clipboard History, Toggle Auto-hide — and plugins' as bare SF
Symbols in the label's colour, stretched to the 36 pt box. Measured in the live panel beside app icons, which
stand 29 × 29 pt in that box: the gear came out 31 × 31, the power symbol 29.5 × 31, `dock.rectangle` 29.5 × 23,
`doc.plaintext` 24 × 31. Each symbol's size followed its own shape, they read as placeholders, and "settings"
put an outline gear directly under System Settings' gear with only the "Dock2" subtitle to tell them apart.
Plugins had no say in colour, a picture could only be base64 in `manifest.json`, and each place drew an icon its
own way — search as given, the dock on a hand-drawn light plate, Settings bare — so a plugin's author could not
predict what theirs would look like.

## Implementation

**One plate.** `IconPlate` is the Finder tile's plate code lifted out of `FinderTileImage`: Icon Composer's
empty-icon plate blended to any colour, a layer with its shadow, drawn on demand at the pixel size it lands
at. The Finder tile, search's rows, "Show all…", plugin tiles and Settings → Plugins all stand on it, so a
row's icon is the 29 pt of the app icons beside it — measured equal, to the pixel, in the live panel.

**Symbols.** White, the `.fill` variant where one exists, semibold, one point size for every symbol (0.6 of
the plate) so SF Symbols' optical balance holds. Fills, at 0.6, beat outlines at 0.55 medium and 0.6 semibold
in a side-by-side in real rows: the outlines looked thin beside System Settings' gear. At one size most symbols
cover 0.53–0.72 of the plate's width, but `playpause.fill` covers 0.93 and overran it, so a symbol whose image
passes 0.86 of the plate (the clipboard's and the dock's, the longest of the rest) is drawn at a smaller point
size. A one-colour palette paints a fill's cut-outs too — the clipboard came out blank — so a symbol is tinted
as a template is (`NSImage.tinted`).

**Pictures.** Clipped to the plate's rect, then cut to its shape by drawing the plate `destinationIn`. The clip
is needed: a blend reaches only where its source is drawn, and without it album art kept the tile's margin
with the plate's corners notched out of it, as the first live capture of Now Playing's tile showed.

**Colour.** For dock2's own commands, chosen with the person over mockups: violet (the app icon's) for what is
about dock2 itself — Settings, Toggle Auto-hide; a colour of its own for a thing dock2 does — Clipboard History
orange; red for Quit. Violet for all four was rejected: as commands multiply it overwhelms. A colour per
meaning everywhere was rejected for Settings, where a gray gear plate under System Settings' gray gear brings
the confusion back. Built-in commands carry an `IconColor`; plugins name a `Tint`, the eight a view already
could, which has no violet, so dock2's colour stays dock2's without a reserved case to police at the
boundary.

**Plugins.** `Icon.symbol` carries a `tint`; the manifest has a `tint`, the plugin's colour, which a symbol
without its own takes — Now Playing pink, Bitwarden blue. A command or result without an icon wears the
plugin's; a plugin without one is a puzzle piece on gray. `{"image": "icon.png"}` names a PNG in the plugin's
folder, manifest only; `PluginStore.manifest(in:)` reads it into `png`, so renderers never see a path, and
`validate()` refuses an absolute path, `..`, an empty component or another extension. Where an icon is drawn
is dock2's call, not the plugin's: among apps' it is plated (`IconImages.plated`), in a view it is a glyph in
its tint (`IconImages.image`). The Rust SDK's `Icon` is now a struct — a flattened `IconSource` and a `tint` —
which serialises to the same one-key JSON; `Icon::Png(…)` became `Icon::png(…)`.

**One answer for a result's icon.** `ResultActions.icon(for:)` replaces the switch in `SearchController`;
"Show all…" asks it too, through a new `ViewHost.icon(for:)` that a list consults before the icon an item
names. Before, "Show all" commands wore a generic ⌘ and clips a generic clipboard.

**`DOCK2_CONFIG` was ignored.** `LaunchEnvironment.setAside()` empties the environment at launch, and
`SettingsFile.standard` read `DOCK2_CONFIG` from `ProcessInfo` after it, so a run under observation used — and
could write — the person's real config. It reads `LaunchEnvironment.variables` now; `lsof` confirmed the run
reads the scratch file. Found when a scratch config's plugin choices did not take.

## Observations

- Settings → Plugins was not seen live: reaching it needs a pointer click. The row is the same
  `IconImages.plated` image the search rows draw, in a SwiftUI `Image`.
- "Show all…" for commands needs more commands than search's section shows, so its icons were not seen live;
  the code is search's own.
- A clip's row in search is still a kind glyph (`ClipboardHost.icon`) — `product/visual.md` marks it Open.
- The plate follows Default's icon style only; Dark, Clear and Tinted are the Finder tile's open question too.
- Compact rows (20 pt, beside a preview) get the same plated images, scaled; not looked at.
- `IconColor(_ tint:)` uses the system colours' sRGB components as Display P3's, as the approved mockup did,
  which reads slightly more saturated than the system's own colours.
