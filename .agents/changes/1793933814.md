# A summon tab in a VM

> Change `1793933814` — 2026-11-05

## Goal

A VM's window leaves ⌘space to the host, so nothing inside could summon dock2 by hand, and someone trying it in a VM needed
a session to run `dock2 summon` for them.

## Implementation

`SummonButton` is a small tab on the right edge of the screen that calls `interaction.summon()`, what the shortcut calls, so
it opens and closes as the shortcut does with no toggle of its own. It is a window of its own, not a view on the stage: the
debug code stays in one file, and the stage's layout takes no part. `outsideClicks` is a global monitor, which hears only other
apps' clicks, so the tab can't dismiss what it is about to toggle; and it can never become key, so the field keeps the
keyboard. It follows a change of screen, since a VM's display follows its window. It shows under `DOCK2_DEBUG=1` and in a VM
(`kern.hv_vmm_present`) alone, so it stands in no capture of a real Mac and needs no flag of its own.

Driven with the real pointer on both VMs: it opens, closes with text in the field, opens again, closes Files, and two clicks
land where they started. Without `DOCK2_DEBUG` the pixel under it is the wallpaper.

## Observations

Following a resize was not driven. There is one tab, for the shortcut: Files and Clipboard have none.

Testing it found that on Tahoe a click elsewhere never dismissed dock2, and why: at rest, dock2 catches clicks meant for the
windows beneath it. A plain window at 400,400 heard its click with no dock2, and with dock2 running and its glass hidden, but
not with the glass showing, and on macOS 27 it heard all three. `GlassLayer` is the size of the stage and its backdrop
`bounds`: `sourceSublayerDefinesBounds`, which Tahoe lacks, is what keeps a backdrop to its shapes. A throwaway patch keeping
it to their extent let the click through, and clipped the pane's corners, since it didn't follow the shapes as they moved.
Not fixed here. `1793931389`'s run through every surface used dock2's own controls and so could not have seen it.
