# The echo without temporary tiles

> Change `1792739791` — 2026-10-23

## Goal

A search result selected that was an app with no tile put a temporary tile, dimmed, at the end of the running
apps, and took it away when the selection moved on. The top hit is selected as each query's first frame
lands, so typing alone grew and shrank the dock several times a second, which was distracting rather than
informative. The echo now shows only on a tile that is already there.

## Implementation

The temporary tile is removed rather than switched off: `TileKind.temporary` and `DockModel.compose`'s
`temporary:` go, and with them everything that only existed for it — `DockView.Tile.dimmed` and
`TileLayer.isDimmed`, `DockView`'s carry-over of a stand-in's icon and dot onto the running tile its app
opened into, and the stand-in's cases in the badge, name, menu and `debug state` kind. `setEcho` maps the app to
its tile kind and rings it only if `slots` holds it; it no longer relays out, so a selection can never change
the dock's shape. Finder's result rings the Files tile, as before.

The alternatives were a setting, or keeping the temporary tile for the top hit only. Both keep the reshape
on every keystroke that changes the top hit, which is what made it distracting.

Checked live with the debug build and `dock2 debug state`, with a dock of Files, Fiber and Ghostty: "calculator"
selected Calculator and left the three tiles as they were, unringed; "ghostty" ringed Ghostty; under "f",
↑ through Fiber, Finder, FaceTime, Feedback Assistant and Show all moved the ring from Fiber to Files and then
cleared it, the tiles the same three throughout.

## Observations

- An app selected in search that is not on the dock now shows nothing on the dock: its row is the only sign
  of the selection.
- These edits were committed inside `6f3453e` (quicker badges/unminimize) by a commit made while this change
  was in progress; this file is its record.
