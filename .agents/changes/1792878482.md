# A way to each prompted permission from Settings

> Change `1792878482` — 2026-10-24

## Goal

Settings → Permissions showed Screen Recording as "Not allowed", and its one button, "Open System Settings…",
opened a pane without Dock2 in it: macOS lists an app there only once the app has asked. dock2 asked in one
place, at the first minimised window the dock matched, and matching reads the hidden Dock and the apps'
windows through Accessibility, which the dock never asks for. On this Mac the installed build's Accessibility
row was off (0), and tccd's log showed both of its runs only checking (`preflight=yes`). Minimising did
nothing. The triggers were hidden. Settings is where "not allowed" is shown, so Settings has to be able to ask.

## Implementation

`PromptedPermission` (Dock2System) covers Accessibility and Screen Recording: the check, the request, the
pane, and an answer — allowed, off, or unasked. While a permission is unasked, Settings shows "Request
Access…", which raises macOS's prompt. Once it is off, Settings shows "Open System Settings…", and dock2 is
listed in that pane. `WindowCapture`'s check and request, and `FileAccess`'s two panes, moved into it. The
dock's own ask is unchanged.

Telling unasked from off takes TCC's private `TCCAccessPreflight`: 0 allowed, 1 answered otherwise, 2 never
asked. It is reached by name, as the charter's other four private APIs are. Measured with a probe app of
its own bundle id:

- `CGRequestScreenCaptureAccess` returns false at once. Only while the preflight says 2 does it prompt (Open
  System Settings / Deny) and list the app, off. Once it says 1, the call does nothing, and tccd logs no
  request.
- `AXIsProcessTrustedWithOptions` with the prompt option raised its prompt even with the app already listed
  off. A repeat from a new process 35 s later raised nothing. `CGRequestPostEventAccess` raised the same
  prompt 18 s after that. `universalAccessAuthWarn` draws this prompt, not tccd, so the log does not show it.
- On macOS 27 a plain `AXIsProcessTrusted()` lists the app in Accessibility, off. After the first launch
  Accessibility is off rather than unasked, and its button is the pane, where dock2 already is.
- In the requesting process the preflight goes from 2 to 1 as soon as the request is made. If that process
  exits while its prompt is still queued, nothing is kept, and the next process reads 2.

Rejected:

- A request button alone. Once Screen Recording is answered, it does nothing.
- A request button next to the pane's. In each state one of them is wrong, and nothing says which.
- Requesting and opening the pane together. The first time, the prompt floats over the pane it would have
  opened.
- Remembering in settings that dock2 asked. Change 1792826616 removed exactly that flag: an ad-hoc reinstall is
  a new app to TCC.

Without the symbol, a permission that is not allowed reads as unasked. Screen Recording's button then
requests, which does nothing once it has been answered.

## Observations

- Not seen in the installed app. This build was not installed, because an ad-hoc reinstall loses this Mac's
  grants, Full Disk Access among them. Build and tests pass. Expected here: Screen Recording "Not asked" with
  Request Access…, and Accessibility "Not allowed" with Open System Settings….
- macOS shows one prompt at a time, and an unanswered one holds the next back. The first launch after this
  reinstall raised the Desktop, Documents and Downloads prompts within three seconds (14:27:28–31). A Request
  Access… pressed then would wait behind them.
- The row re-reads when pressed and when dock2 becomes active again, which answering the prompt causes. A
  prompt left open leaves "Request Access…" up, and pressing it again does nothing.
- TCC can say allowed while `CGPreflightScreenCaptureAccess` still says no, until dock2 relaunches. That reads
  as off, and the button opens the pane, which shows the permission on. Untested.
- No tests. A test runner is the terminal as far as TCC is concerned, and the terminal holds Screen
  Recording.
