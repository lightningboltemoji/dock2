# A global shortcut for any plugin command

> Change `1793678554` — 2026-11-02

## Goal

dock2 had two global shortcuts, summon and Clipboard History, each registered by `AppController` on its own.
A plugin could add commands to search, but none of them could be put on a key, even when the key is the whole
point: Now Playing's Play/Pause, Bitwarden's Search Vault. Settings → Shortcuts listed the two, and the product
already had "a shortcut per command" marked _Later_. This change makes every command a plugin declares
bindable, and turns the Shortcuts section into one tree of everything bindable: Dock2 → Open Dock2,
Clipboard History → Open Clipboard History, then each plugin → each of its commands.

## Implementation

**Every declared command is bindable, with no manifest field.** A command is already a plugin's declared,
user-triggered action, and each one already copes with arriving from nothing: Bitwarden's `search` shows
the sign-in form while signed out. An opt-in flag would be a second declaration for authors to remember,
deciding something that is the user's call. The tree lists hidden commands too, since Search Vault is the one
you'd most want on a key and it stays hidden until sign-in. A binding sends `command`, which `isAction` already
treats as the user acting, so a view it answers with brings dock2 up through the existing `summoning` path.
Neither the host nor the SDK changed.

**Bindings live in the plugin's own table**, `[plugins."<id>".shortcuts]`, keyed by command id, beside
`tiles`. That way they get the plugin choices' rules for free: they follow the person between Macs, a table
for a plugin not installed here is carried untouched, removing a plugin keeps them, and a key for a command
an update dropped is a diagnostic, not silently lost. The rejected option was one `[shortcuts]` table for
everything. It would have meant moving `clipboard.shortcut` and `general.summon`, which v0.1 and v0.2 already
write and share between Macs, and keying plugin entries by a dotted id inside a dotted table. The tree is a
view over keys that stay where they were. A shortcut is the one plugin choice the plugin never hears of, so
`PluginStore.choicesChangedInFile` compares `heard` (the choices without shortcuts) to decide what to restart.
Re-binding a key by hand no longer reloads Now Playing.

**`GlobalShortcuts` owns every registration.** The summon shortcut's Spotlight takeover moved there from
`AppController`, so one place sees every chord. That matters because of what Carbon does, measured with a
probe in this session: `RegisterEventHotKey` returns `-9878` (`eventHotKeyExistsErr`) for a process's second
registration of a chord, yet a second *process* registers the same chord with `noErr`. So do ⌘⇥, ⌘Space,
⌃↑ and ⇧⌘3, whatever the system does with them at press time. Two dock2 actions on one chord would have shown
the second as "macOS would not let Dock2 have it: the system or another app already uses it", which the
probe shows is not why. `ShortcutAction.resolve` (Core) settles dock2's own clashes first: dock2's actions
before plugins, plugins in install order, commands in manifest order. The rest are reported as `.taken(by:)`,
and Settings names the holder. The refusal text no longer gives a reason. `apply()` keeps every registration
whose chord did not change, drops stale ones before registering, so a chord can move between actions in one
pass, and retries refused ones. It runs on any change to the summon shortcut, the clipboard's shortcut, the
open tables, or the plugin store's `onChange`, which covers install, remove, on/off, suspension and file
edits. Registration follows `isEnabled`, so a plugin that is off or suspended doesn't swallow its chord doing
nothing.

The summon row in the tree is a recorder: ⌘Space recorded is `.commandSpace`, the takeover, as the codec already
reads `"cmd-space"`. General keeps its three-way picker and Clipboard keeps its row, so the tree is the one place
with everything, not the only place.

## Observations

- Not yet seen live. This session couldn't replace the running dock2 (a debug build on the real config), so
  none of these has been checked on screen: the tree's look, a plugin command firing from its key, a "taken"
  message, or the Spotlight takeover's `kill -9` path after the move. The unit tests cover resolution,
  reading and writing the table, and the no-restart rule. The takeover code moved without changing what it
  does, but `CLAUDE.md` asks for the crash path to be tested after touching it.
- dock2's other built-in commands — Settings, Toggle Auto-hide, Quit — are not bindable. Each would need a key
  of its own in the schema; the product marks them _Later_.
- Whether a chord the system's own shortcuts hold (⌘⇥) reaches dock2 at press time once registered is
  unmeasured. Registration succeeds, so Settings says nothing about it.
- A plugin can't draw outside the panel ([views](../product/plugins/views.md#what-a-plugin-cannot-do)), so a
  "confetti" command can only toast, open a view, or act through a capability.
