# A demo plugin, every view in every variation

> Change `1793690314` — 2026-11-02

## Goal

The four view kinds (list, detail, form, grid) are to be improved in how they look and how they are used,
and there was no single place to see them. Each existed only where a real plugin happened to use it: Now
Playing's detail, Bitwarden's form and list, the test guest's grid. No screen exercised the variations a
plugin can ask for: every icon kind, accessories together, empty and loading states, owner filtering, a form
becoming a detail, pictures at 1× and 2×, refused chords and effects. This change adds a plugin that does,
loaded only by debug runs, as a fixture for that work now and for regressions later.

## Implementation

**Where it loads from.** Three options were considered. `dock2 plugin dev Plugins/demo` needs no code, but
installs into `~/Library/Application Support/dock2/Plugins`, which the installed app shares, and it stays
after the debug run. Shipping it as first-party would put it in every release bundle, and a debug run with a
fresh config would start it off each time. The option taken is a third root: `make plugins` builds the demo
into `.build/dev-plugins`, which `make app` never copies, and `PluginStore` reads that root only under
`DOCK2_DEBUG=1` and never from inside the bundle. A plugin's origin is now `PluginOrigin` (first-party,
development, installed) instead of `isFirstParty`, because the three differ in two ways: a first-party plugin
starts off while the other two start on, and only an installed one can be removed or installed over. Settings
says "Debug runs only" for a development plugin. The `DOCK2_DEBUG` key moved from `ControlRouter` to
`LaunchEnvironment` (`isDebug`), since two things read it now.

**The plugin.** Each screen implements `Screen` (render, opened, action, submit, filter, timer, popped,
closed) and is listed once in the gallery's table with what it covers, which is also the gallery's preview.
The router finds a screen by the view id up to its first slash, so pushed views (`<screen>/pushed-2`) and
timers (`<screen>/tick`) reach the screen that made them. A screen is made fresh on opening and dropped on
closing, so a capture is repeatable. There are 21 screens: seven lists, five details, five forms, four grids
and one feedback list, plus the gallery itself, which is a list with a preview.

**Pictures.** A plugin reads no files, so the demo draws its PNGs: a gradient "album art", a bar chart, a
poster, hairline stripes, and eight thumbnails. The encoder uses stored deflate blocks, about seventy lines
with no dependency. The pictures are uncompressed, about 1 MB raw in all, and are made in `started`, under
the 1 s background budget rather than the 50 ms an action gets. A `pHYs` chunk at 144 dpi tells AppKit that
a 2× picture is half its pixel size in points, so 1× and 2× can be compared.

**SDK.** The demo needed builders the SDK lacked, and other plugins will too: `Field::options` (a choice
field previously needed a struct literal), `Form::new/title/field`, `Grid::new/title/columns/actions`,
`GridItem::new/title/actions`, `List::actions`, `Item::accessory_icon` and `Detail::link`.

Tests: Rust tests check that every screen renders under its own id, that every kind has a manifest command,
and that a saved form becomes a detail in place. A Swift test checks that a development plugin starts on,
cannot be removed or installed over, and writes nothing to the config file.

## Observations

Driven live with `DOCK2_DEBUG=1`, using a scratch config. A run without the switch had no demo, and no call
overran its budget. The demo surfaced these, none of them fixed here:

- **A list read from the top loses its selection off-screen.** After twelve ↓ in Every Row, the selected row
  (the wide picture, as ↩'s toast confirmed) sat above the visible rows, which showed rows 17 to 24.
  `revealSelection` in `fromTop` mode is the suspect.
- **A form has no scroll.** Every Field submitted empty puts three errors under eight fields. The stack then
  overflows the panel's height, and `NSStackView` squeezes the title and the Name and Email fields to slivers
  and the folder field's text to nothing. More Fields Than Fit shows it without errors.
- **An app's or a file's icon as a detail's image is 32 pt.** That is `NSWorkspace`'s default size, while a
  symbol is drawn at the detail's 160 pt.
- **A detail's buttons with an icon sit lower than those without** (Next Image and Next Body against Hide
  Metadata).
- **With an image, metadata and a scrubber, the body gets a short scroll area,** and the metadata scrolls
  under the scrubber after two rows.

Not looked at: the grid's column changes, the empty grid, the bare list's placeholder, the light appearance,
Reduce Motion, and how long a call that carries every picture takes. The last was kept under budget but not
timed. The demo does not cover tiles or search results. It is about views, though either would fit as
another screen kind.
