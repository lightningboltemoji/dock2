# A form moves on its first showing

> Change `1792650318` — 2026-10-21

## Goal

With Lava lamp, the first summon after launch showed the droplets' glass frozen in one shape while the
magnifier drifted about inside it. Every showing after the first dismissal looked right. It happened when the
dock was already up, so the field entered at once rather than waiting for the dock to arrive.

## Implementation

`GlassView` sized its `GlassLayer` in `layout()`, which AppKit runs later. Before the first showing the layer
was still zero by zero. `PanelController.show` sets the glass view's frame and, with the dock up, starts the
form in the same turn, so `GlassLayer.play` built its tree at zero size and put the keyframes on it. The
layout pass then sized the layer, `layoutSublayers` found its sublayers the wrong size and rebuilt the tree,
and the new elements sat still at the track's last frame. The field's magnifier and text, played on
`FieldView`, kept moving. Summoned with the dock away, `show` calls `setGlass(nil)` first, which runs
`update()` and sizes the layer, so that path never showed the bug. After the first dismissal it never showed
either, for the same reason.

`GlassView` now overrides `setFrameSize` to size the glass, the overlay and the plain fill as its frame
changes. `layout()` still runs `update()`, which by then finds nothing to resize. Two alternatives were
rejected. Calling `layoutSubtreeIfNeeded` in `show` would fix this one caller but leave the trap for the
next one. Keeping keyframes through a rebuild in `GlassLayer` would mean recording every track, and only a
display change resizes the glass while it is playing. Every form, and the glass's own rise on that first
entrance, goes through the same `play`, so the fix covers them all.

## Observations

- Measured at 120 fps on the debug build with Lava lamp, the dock held up by `dock2 debug reveal on` and the
  field brought in by `dock2 summon`. Before the fix, the first showing's droplets did not move for 5 s and
  the second showing's did. After it, both showings' droplets drift, part and merge, the magnifier in the
  biggest. Drop and Gem were not recorded.
- `GlassView.update()` still stops the plain fill's keyframes (`updatePlain`) on every layout. Under Reduce
  Transparency or Increase Contrast, a layout during the panel's growth would freeze the fill's path. That
  was not seen and not changed.
