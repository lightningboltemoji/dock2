# Settings → Icons, laid out

> Change `1794561087` — 2026-11-13

## Goal

Settings → Icons (`1794556735`) worked but was built without being looked at. In the `golden-gate-base` VM (macOS
27.2) each row's label sat at the top of a tall row while its well sat in the middle. Most rows showed the same icon
twice, small beside the name and again in a grey box. At the well's 32 pt the strawberry drew one screen pixel per
Cairo pixel and the anchor two, so the two pictures looked unrelated in size. In the picker, a translucent square
marked the selection, unrelated to the icon's shape. The scrollbar lay over the last column and the bottom row was
clipped. Colour and Fill were loose lines, and a chosen file showed only as a path.

## Implementation

- **The row** follows the plugins' header row, which is the house pattern: an icon, a name, a caption, then a
  control. The icon is the one the tile wears, and the caption says what that is: its own icon, Finder's icon, a
  picture (with "unfilled" when it is), or a file with its pack name. A file `TileIconFiles` has a diagnostic for is
  marked with a warning glyph. Change… opens the choices, and so does a click on the icon. `LabeledContent` is gone:
  in a grouped `Form` it top-aligns its label against tall content, which caused the misalignment. Showing the own
  icon beside the worn one was dropped too: the name identifies the app, and the picker shows the own icon first.
- **40 pt.** The pixel scale steps with size. At 64 px, 27 of the 59 pictures get one screen pixel per Cairo pixel
  and 31 get two. At 80 px, 54 get two. Rows and picker cells both draw at 40 pt, so a picture looks the same in
  each, and as it would on a 40 pt tile.
- **The picker** puts the choices that are not pictures across the top: the own icon, Finder's for Files, the file
  worn if any, and Choose File…. The pictures go below, nine across, which fits 59 in seven rows with no scroll view.
  Colour and Fill share a row under them. The selection is a 2.5 pt accent ring concentric with the plate (412/512
  of the icon, corner 22.5% of the plate). The focus effect takes the same shape (`.contentShape(.focusEffect, …)`),
  so keyboard navigation draws a rounded ring rather than a square. A refusal is a `Label` with an orange triangle,
  not red text. A pack's icons have their names under them.
- **A fix found while driving it.** `pack` and `problem` were single `@State` values shared by every row. A file
  refused in Notes' picker then showed as Safari's refusal when Safari's picker opened. A pack opened in one row and
  left unpicked would likewise show in the next row's picker, and a click there would apply it to that row. Both are
  now kept with the key they came from and shown only there. Opening a row from Change… or its icon clears them.
  They are not cleared in `onChange(of: navigation.icon)`, because `choose` sets `navigation.icon` itself, to
  reopen the popover the Open panel closed, and clearing there would wipe what `choose` had just set.

Verified in the VM on the debug build, light and dark, with `AppleKeyboardUIMode` 0 as on the host. The image ships
with keyboard navigation on (3), which puts the focus ring on the first cell whenever the popover opens. It was set
back to 3 afterwards.

- **Rows:** a picture, a pack's icon, a catalog of one, a missing file (marked), Finder's icon and the own icon, each
  captioned.
- **Picker:** Dog chosen, then Fill off, then the own icon. These wrote, rewrote and removed TextEdit's line. Finder
  was chosen for Files. A pack went through Choose File…, and picking red wrote `{ file = "icons/pack.car",
  name = "red" }`. A file that isn't a catalog was refused with its reason. Hover shows a wash. Colour and Fill
  are disabled unless a picture is worn.
- **Change Icon…** on Preview's tile opened Icons at its row, with Dog ringed and Preview's violet taken up.
- **The fix:** a refusal on Notes no longer showed on Safari or on Notes reopened. A pack opened on Notes didn't show
  on Safari.

## Observations

- A pack's cell is ringed by its icon's name alone. A second pack with an icon of the same name shows it as worn.
- On a 1× display a 40 pt icon is 40 px, and most pictures get one screen pixel per Cairo pixel. That was not seen,
  since the VM is 2×.
- A refusal shown in a row stays there when the row is reopened through a tile's Change Icon… while Icons is still
  on screen. Only Change… and the row's icon clear it.
- Not driven: a `.car` dropped on a row, and the drop ring.
