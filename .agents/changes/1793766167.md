# `files`: the folders the user picks

> Change `1793766167` — 2026-11-03

## Goal

The sixth step of the capabilities plan (`design/plugins.md`). `files` was a reserved name that granted
nothing. A notes plugin needs to read, and perhaps write, a folder the user chose, and hear when it changes.

## Implementation

**What it reaches.** The folders that the folder settings named in `files.folders` hold now, and no others. A
setting left empty grants nothing ("no folder is chosen for it in Settings → Plugins"). Every path goes through
`PathGuard` on a serial queue of the host's own: absolute, no `..`, links followed, inside a granted folder.
Every event carries the path as resolved. The queue is off the main thread because a folder macOS guards may
prompt, for Dock2, and wait.

**Effects** (`PluginFiles`):

- `fileRead`: up to 8 MiB a read (`readLimit`, the design's open value), from `offset`, `length` if given,
  and the file's whole size, so a plugin reads the rest by range.
- `fileList`: a folder's entries, sorted, each with its kind as `lstat` sees it (a link stays a link), size
  and modification time. At most 10,000, then `truncated`.
- `fileStat`: one entry, or nothing.
- `fileWrite`, with `"write": true`: the folders it lacks are made inside the granted one. The file is
  replaced whole through a temporary file beside it renamed over it, or appended to.

The last step is opened with `O_NOFOLLOW`, and `rename` replaces a link rather than following it. A link
swapped in after `PathGuard` resolved the path is therefore not written through, as the second step's change
said this one would ensure.

**Watching.** `watch(id, path)` takes a folder inside a granted one. FSEvents reports its file-level changes
as `fileChanged(watch, paths)`, 0.3 s at a time. `FolderWatcher` gained a form that hands over the paths, and
a `stop`. A watch is held under `files`, eight to a plugin. A revoke ends it. So does a folder setting moving
elsewhere: `PluginHost.setSetting`, which Settings now calls, ends every watch the new folders no longer
admit before the plugin hears its settings.

**The SDK** has `file_read`, `file_read_range`, `file_list`, `file_stat`, `file_write`, `watch`, `unwatch` and
`FileEntry`. The plugin's entry type in Core is `PluginFileEntry`, since `FileEntry` is Files' own.

Tested against a real folder with a link out of it: written, appended, read back as "hello world", listed with
the link as a link, a missing file as nothing, the link out and a climb refused without a byte of what lies
outside, a watch hearing a new file and ending when the setting moved or `files` was revoked, and a read
capped at 8 MiB that says the whole size.

## Observations

- The XPC test waited a fixed 200 ms and failed once the whole suite ran in parallel with `run`'s 4 MiB test.
  It now waits for what it expects, as the new tests do. The older host tests still wait a fixed time.
- The sheet's note about macOS's prompt is the same for every `files`: it does not yet look, through
  `FileAccess`, at whether the folder chosen is one macOS guards and whether Dock2 already may.
- iCloud Drive's folders were not tried; a file not yet downloaded reads as what the file system gives.
- A write is atomic per file. A folder of several files written in turn may be seen half-done by another
  reader.
