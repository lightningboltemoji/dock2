# Servers, as Finder shows them

> Change `1793697353` — 2026-11-03

## Goal

Files treated a file server's shares as unrelated disks. With a Synology's Media and Misc mounted, the places
pop-up listed Media and Misc, each with no ⏏, and nothing else from it. Finder's sidebar shows one Synology with
⏏. Its server window lists every share the server offers, home and Time Machine included, mounts one on
selection, and says who it is connected as. Network discovered servers not yet connected. In dock2, eject was ⌘E
alone, run synchronously on the main thread, and it always sent the tab Home.

## Implementation

Everything rests on what macOS exposes, measured against the Synology first. Finder was driven through
Accessibility, with screenshots.

- **Grouping.** A share's `volumeURLForRemounting` names its server and user. The server is `smb://<host>`, which
  matches the host Bonjour gives a discovered server, so a connected server and an announced one are the same row.
- **Listing shares.** The SDK's `NetFSPlugin.h` describes the NetFS plugin interface. Loading the SMB plugin with
  `CFPlugIn` and calling `OpenSession` without UI, then `EnumerateShares`, returned Finder's four shares, with
  mounted state and mount paths, in 0.26 s. It needs no private API and no running `smbutil view`. Swift's
  `NetFS` module leaves that header out, so the `Dock2NetFS` system-library target carries a module map for it.
  A C shim was the alternative, and isn't needed.
- **Unmounting.** `FileManager.unmountVolume` on one share unmounted all three: it disconnects the server. That
  was found by accident on the user's NAS; Media and Misc were remounted within seconds. `unmount(2)` unmounts
  the share alone and still posts `didUnmountNotification`. So a share uses `unmount(2)`, and Disconnect
  unmounts share by share rather than relying on the side effect. A disk keeps `.allPartitionsAndEjectDisk`,
  Finder's eject. All of it runs off the main thread.
- **Mount on selection.** Selecting `home` in Finder's server column through Accessibility mounted it and listed
  it. Files does the same rather than adding a Connect step that Finder lacks.
- **The sign-in window.** It belongs to `NetAuthAgent`, which activates, and dock2's stage is at the Dock's window
  level, above it. Staying up beneath it, as first designed, would have covered its Connect button. So dock2
  steps aside, and Files comes back when the mount it asked for succeeds. A cancel doesn't bring it back. On the
  way back, the terminal's activation arrived *after* Files had taken the keyboard over it, and it dismissed
  Files again. `InteractionController` now treats an activation of the app that was in front as it took the
  keyboard as an echo, not a switch. A real switch still dismisses (Finder brought forward, checked).

A column's folder may now be a URL that is no file's: `network:`, `smb://<host>`, or a share's address before it
mounts. `URL.canonical` leaves those alone, and `FilesState.relative` compares scheme and host first, so a share
named `home` is never the local `/home`. That matters: the folder watch, the access checks, the item count and the
icon would all have read the path `/home`, and opening `/home` can trigger its automount. A share's chain
starts at its server (`go(to:root:above:)`), and `Servers.parent(of:)` answers ⌘↑ and "which column holds this
row" in place of `parentFolder`. The column's Allow Access… button became a general message button, for Try Again,
Connect, Connect As… and Local Network's pane.

The places pop-up's ⏏ is a view row, `PlaceMenuRow`, because an `NSMenuItem` cannot hold a button. Its geometry
was measured off the native items beside it: 24 pt rows, a highlight inset 5 pt with a 7 pt radius, and titles
30 pt in. A label draws 2 pt inside its frame, so the label's frame starts at 28 pt. The highlight is an
emphasized `.selection` visual-effect view; it came out pixel-identical, (65, 143, 248), where `controlAccentColor`
and `selectedContentBackgroundColor` both missed. Native items lose their check column when the only checked
item is a view, so the view's item keeps its state too. `MenuRow` now covers both this row and `MenuPills`.

A host with a space or an apostrophe gives a nil URL through `URLComponents.host` and through `percentEncodedHost`.
Only `encodedHost` takes it.

## Observations

Seen live in the debug build, against the Synology: the server column, `home` mounted on selection and
ejected with ⌘E (Media and Misc untouched), Network through ⌘↑ with Bonjour's Synology carrying ⏏, the pop-up
with Synology once and ⏏ beside it, ↓ ↩ choosing that row, a disk image's ⏏ in the pop-up ejecting it, Connect As…
through macOS's window and share picker with Files coming back, and `smb://` typed in the field.

- Untried: a server not connected (its guest listing, Not Connected), one that does not answer (`Cancel` at
  15 s), a server whose name has a space, NFS, and Local Network from the bundle, which may govern mounting
  too (`design/files.md`).
- The pop-up's ⏏ on a server was not pressed: it would have disconnected shares the user had mounted. Its path
  is the disk image's row and the share-by-share eject, both seen.
- The server column has no header like Finder's ("Connected as: tanner", Disconnect). Who it is connected as
  is kept (`Server.user`, `Listing.user`) but not shown; Connect As… and Disconnect live in ⌘K.
- `TakeoversTests.anOlderJournalIsCompletedBeforeTakingOver` failed once with a permission error on its temporary
  folder, and passed in every later run. That code is untouched here.
