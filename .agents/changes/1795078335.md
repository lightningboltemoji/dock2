# A running app found where it runs

> Change `1795078335` — 2026-11-19

## Goal

Clicking Tart's tile did not bring Tart forward: CoreServicesUIAgent showed Finder's "The file can't be found."
instead, and dock2 logged `could not open tart.app: … there is no such file`. LaunchServices' log named the URL
dock2 opened, `/opt/homebrew/Cellar/tart/2.41.1/libexec/tart.app`. Homebrew had upgraded Tart to 2.42.0 four days
into dock2's run and deleted 2.41.1. `AppDirectory` looks an app up once and keeps the entry. Only
`forgetChanged` forgets one, fed by the catalog, which watches `/Applications` and the other app folders and never
the Cellar. Tart's entry kept the old URL, and every click and every "Show in Files" went there.

## Implementation

Running apps now reconcile the directory, as the catalog's folders do. `DockController.runningChanged` calls
`AppDirectory.forgetMoved(running.apps)`, which forgets each entry whose URL is not the path its app runs from.
`locate` prefers the running copy's `bundleURL`, then LaunchServices' preferred copy, then the path. Without that
order, an app with two copies, one running from elsewhere while LaunchServices prefers the other, would be
forgotten and looked up at the same wrong copy on every change to the running apps. With it, a click on a
running app's tile opens the copy that runs, which brings that process forward.

The comparison works on `standardizedFileURL` paths and does no I/O. Statting each entry's URL in `entry()` was
rejected: it would run on every relayout, and an entry on a stalled network mount would block the main thread.

Measured in the `golden-gate-base` VM with a probe app (`test.dock2.probe`). It was run from `/tmp/probe/1.0`,
quit, moved to `/tmp/probe/2.0`, run again, and Finder brought forward. Then `debug click tile:Probe`. Before
the change: `could not open Probe.app: … no such file`, Finder still in front, and the same dialog on screen.
After: Probe in front, nothing logged. `anAppRunningFromElsewhereIsLookedUpAgain` covers `forgetMoved`.

## Observations

- A pinned app outside the catalog's folders that moves while it is not running keeps its stale entry until it
  runs again. A click on its tile then fails as before, and it would run from the new place only if launched
  some other way. Covering that means re-locating at the click, or watching each such entry's folder.
- Under this rule an app with two copies wears the running copy's icon while it runs. The catalog's next change
  can forget it back to the copy in `/Applications`, after which it is looked up at the running copy again.
- Not measured: whether a running Safari reports its `/Applications` symlink or the cryptex path as
  `bundleURL`. If the latter, its entry is looked up once more after it launches, then holds.
