# A paste lands where Finder's columns paste

> Change `1794636416` — 2026-11-13

## Goal

With a folder selected, ⌘V pasted beside it rather than into it. Files pasted into `tab.folder`, the column with
the keys, and selecting a folder opens its column while the keys stay behind, so the paste went to the folder's
parent. Finder pastes into the selected folder. ⇧⌘N had the same fault.

Finder was measured in the `golden-gate-base` VM (macOS 27.2), column view, with a file copied by Finder's own ⌘C:

| Selected, keys in `PasteTest`'s column | ⌘V lands in | ⇧⌘N makes it in |
| --- | --- | --- |
| `Empty`, an empty folder | `Empty` | `Empty` |
| `Full`, a folder with a file | `Full` | — |
| `file.txt` | `PasteTest` | `PasteTest` |
| `Full` and `src` | `PasteTest` | — |

After the paste, Finder selects nothing new. With a folder selected, the keys stay on that folder and the pasted
file shows unselected in its column. With a file selected, that file stays selected. ⇧⌘N into a selected folder
moves into it, selects the new folder and starts its rename.

## Implementation

- **`FilesState.Tab.destination`**: the folder in the column just past the keys, else `folder`. A column opens
  past the keys only when one folder is selected there, so this is Finder's rule as measured. `deepest` was the
  nearer candidate and is the same folder in every case but one: ⌘↑ from the first column puts a column before a
  selection that is already open (`[/Users ▸me, me ▸a, a]`, keys in `/Users`). There `deepest` is `a`, while the
  folder selected under the keys is `me`. Finder's ⌘↑ re-roots the window instead, so it has no matching state. The
  rule that holds wherever the two can be compared is the folder selected under the keys.
- ⌘V, ⇧⌘V/⌥⌘V, ⇧⌘N and ⌘K's New Folder all use it. Each is gated on the destination being a file URL rather than on
  `tab.folder`, so a mounted share selected in a server's column takes a paste. `actions(for:in:)` gets the
  destination as a separate `newFolderIn`, not as its folder. Its folder also decides `networkActions` and Connect
  As…, and passing the destination there would drop Connect As… from ⌘K on a selected share. A right-click's New
  Folder stays positional: the column clicked.
- While searching, the columns are hidden and the field says "Search “folder”", so a paste goes to `tab.folder`
  as before rather than to a folder selected out of sight.
- A paste now lands through the same `put` as a drop and Copy to (renamed from `drop`). What lands in the keys'
  folder is selected, as before. What lands in a selected folder leaves the selection alone, as Finder does and as
  a drop on a folder row already did. Before this, `select(made)` would have revealed the pasted items and moved
  the keys into the folder.

Verified in the VM on the debug build, driven with `dock2 files` and `dock2 debug key`. In each case the keys were
put in `PasteTest`'s column by `dock2 files ~/PasteTest/<folder>` then ←:

- **Empty selected:** ⌘V landed in `Empty/a.txt`. Empty stayed selected and a.txt showed in its column. A ↓ then
  moved the selection to Full, so the keys had stayed in `PasteTest`'s column. The baseline build from `b1df07d`,
  run through the same steps, put it in `PasteTest/a.txt`, which reproduces the report.
- **Full selected:** `Full/a.txt`.
- **⇧⌘N with Empty selected:** `Empty/untitled folder`, selected, its name being edited.
- **A new folder selected with its column open:** ⌘V went into it.
- **file.txt selected:** `PasteTest/a.txt`.

## Observations

- After a paste into the keys' folder, dock2 still selects what landed. Finder leaves the selection where it was.
  This was left alone, because it is dock2's rule for every operation (`select(_:)`), not just a paste.
- After an operation that selects a single folder (⌘D, a paste), that folder's column stays closed (`select`'s
  `opens: false`), so a following ⌘V lands beside it rather than in it. Finder always opens a selected folder's
  column, so it has no matching state.
- Not driven: ⌘K's New Folder, ⇧⌘V, a paste into a mounted share from a server's column, a paste while searching.
