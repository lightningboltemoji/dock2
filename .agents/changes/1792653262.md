# Dock2 is the name people see

> Change `1792653262` — 2026-10-22

## Goal

The bundle was `Dock2.app`, but its `CFBundleName` and `CFBundleDisplayName` were `dock2`, and so was every
string in the GUI. macOS shows the plist's name rather than the file's: `mdls` reported
`kMDItemDisplayName = "dock2"` for `Dock2.app`. So Spotlight, the menu bar, ⌘⇥, Force Quit and the privacy
lists in System Settings all said `dock2`. The product is styled Dock2 wherever a person reads it; `dock2`
stays for the CLI.

## Implementation

`CFBundleName` and `CFBundleDisplayName` are `Dock2`. `CFBundleExecutable` stays `dock2`: the guard is launched
from `Bundle.main.executableURL`, and the CLI is that executable through a link. The GUI's strings changed
casing and nothing else: the app menu, the platter's menu, the Quit command and the subtitle on every built-in
command, the onboarding, the Settings window and its copy, Files' notices and its Full Disk Access banner, the
clipboard notice, the reserved-key names, plugin errors, the Bitwarden plugin's description, both bundled
plugins' `author`, and the clipboard's source name for dock2's own copies.

Two less visible labels changed too. The keychain item's label shows in Keychain Access and its prompts. The
Bitwarden device name shows in Bitwarden's device list and its new-login emails; `deviceIdentifier` is a
separate field, so the account still sees the same device.

An audit of every runtime use of the name found nothing that depends on it. The settings domain, keychain
services, the login item (`SMAppService.mainApp`) and every "is this me?" check use the bundle identifier.
Self-exclusion uses the pid. Application Support, Logs, the socket and the lock are hard-coded paths. No user
data moves.

The CLI's usage and messages, logs, paths, identifiers, `DOCK2_*`, the release archive's name and the
`.dock2plugin` extension stay lowercase.

## Observations

- Items saved before the change keep their old text: clipboard rows that dock2 copied still say `dock2`, the
  existing keychain item keeps its old label, and a Bitwarden device registered before the change keeps its
  old name.
- `AppCatalog` lists Dock2.app among the apps, so its own search result now reads Dock2. That is harmless, and
  matching ignores case.
- Checked on `dist/Dock2.app` through `mdls`, `FileManager.displayName` and the built plist. Not checked over an
  installed `/Applications/Dock2.app`, which LaunchServices may keep showing as `dock2` until it is
  registered again.
- `make test` passes, 133 tests. The Rust change is one string in the Bitwarden plugin, which `make test`
  builds but whose own tests were not run.
