# A global shortcut for Files

> Change `1793866893` — 2026-11-05

## Goal

Getting to Files from another app took ⌘space and ⌘1, or a reveal and a click. Asked for a shortcut that toggles it.

## Implementation

`ShortcutAction.files`, on `[files] shortcut`, none by default like Clipboard History's: a global chord is taken from
every app, so dock2 doesn't choose one. It resolves after Clipboard History's and before the plugins, with a row in
Settings → Files and a node in Settings → Shortcuts wearing the tile's icon.

What it does is `DockController.useFinderTile`, which is `use(.finder)`. That already had the toggle: `use` closes what
the open tile opened, and otherwise opens Files, which is why ⌘1 works as one. Rejected: a `toggleFiles` beside `showFiles`
in `InteractionController`, which would be a second statement of that rule, with `views.top === files` standing in for
`kind == open`. So a press closes "back to wherever that came from": over a query, to the query, and from nothing, to
nothing. Always dismissing was the other reading of "toggle", and it would disagree with the tile.

`dock2 files` stays a one-way open: as `summon` never dismisses, a verb that closes depending on what is showing is no
use to a script.

Measured first, that toggle had a hole. `showFiles` pushed Files whenever it was not on top, and Files is one object, so
with Clipboard History over it the stack became `[Files, Clipboard History, Files]`. The next press popped to Clipboard
History rather than closing, and `closed()` had run on a Files still on the stack. A click on the tile could already do
this; a global chord next to Clipboard History's makes it two keystrokes. `ViewsController.push` now holds the invariant,
one screen once: pushing one already there closes what is over it and keeps its `Entry`, so Files returns to where it
first came from. It is in `push` rather than `showFiles` because that is the level that owns the stack.

Driven on a debug build on its own config, the chord posted to the HID tap, since `debug key` stops short of Carbon, with
⌘space as the control. From rest, from a summoned empty field, over a query (it comes back with its 7 rows), with a path
being typed in Files, and under Clipboard History, filtered or not and from a query or from nothing, it opens and then
closes in one press each. `debug key cmd+1` does the same from an empty field. The rows, a clash ("Open Clipboard History has it already"), a live
rebind and a clear were checked in Settings and by `debug state`; a cleared chord does nothing.

## Observations

- `ViewsController` is in `Dock2Shell`, which has no test target, so the stack's invariant is only what was driven above.
  `Dock2CoreTests` covers the setting and the order chords resolve in.
- `showClipboardHistory` builds a new screen each time, so `push`'s identity check doesn't reach it: pressed twice, it
  stacks two and takes two Escs. Its shortcut isn't a toggle at all, which this change makes the odd one out.
- A filter typed in Clipboard History stays in the field, hidden under Files' bar, when Files comes back to the top. Nothing
  read it in any of the runs, and letting go clears it.
- Posted to the HID tap, a function key needs `maskSecondaryFn` or the hot key doesn't fire. That is the post's fault: `f19`
  works with it.
- Not tried with a real hand on the keyboard, while a menu is up, or during a drag.
