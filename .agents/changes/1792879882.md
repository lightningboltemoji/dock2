# The calculator

> Change `1792879882` — 2026-10-24

## Goal

Typing "33+24" or "1 lb to oz" into search found nothing to answer it. The product had a calculator and unit
conversion as _Later_, a first-party plugin once the plugin interface had proven itself. It is built here
instead, as a source of dock2's own.

## Implementation

**fend, not our own.** The candidates, with licences checked at the source: fend (MIT, no dependencies,
arbitrary precision, forgiving about input); Numbat (MIT/Apache, a strict, statically typed unit language);
SoulverCore (Raycast's, the best natural language, a closed binary needing a licence for public use);
libqalculate (GPL C++); rink (MPL code over a GPL-3 unit database). fend and Numbat were run natively on the
same questions. fend answered `100 C to F` (212 °F), `15% of 80` and `2^64` exactly. Numbat read C and F as
coulombs and farads, had no "of", gave 1.84467e+19, and loads a prelude for 29 ms at start. fend did all 16 in
0.87 ms. Building our own was rejected: the parser is the easy part, and the unit tables, aliases, offsets and
exact arithmetic that fend already has are the rest. fend 1.5.9's licence was read in its own `Cargo.toml`: MIT,
with no features at all. Its GPL unit-data feature belonged to the 0.1 series.

**Built in, not a plugin.** An answer has to be the top hit, ahead of every source. A plugin's results stand in
their own section below dock2's, and letting a plugin claim "this query is mine" for anything typed is a power
no guest should hold. It also needs no `query` grant, and stays clear of the engine migration under way.

**When it answers.** fend answers far more than questions. Run over every prefix of the 96 app names on this
Mac, 58 came back answered: "a" as an ampere, "G" a billion, "e" 2.718. Run over names and quantities with
digits, it answered "4k" 4000, "3pm" picometres, "2fa" femtoamperes, "5gb", "12 inch". `Calculator.asks` wants
a digit and more than a number with a word on it. fend's own `evaluate_preview_with_interrupt` does the rest:
it drops errors, the input restated, unit types, and anything over a line or 50 characters. Real questions —
`33+24`, `1 lb to oz`, `20% of 50`, `sqrt 2`, `70 kg in lb`, `1 day in hours` — all pass. "2 pi" is the casualty.

**Safe for any input.** Two measurements shaped `dc_answer`. fend parses by recursion. On a 512 KiB stack, a
dispatch queue's, 100 nested parentheses overflowed and aborted the process. Binary-searched on 8 MiB, the
worst shapes, `(` alone and `(…)` pairs, cost about 4.3 KB of stack per character of input. So a question past
256 bytes is refused, and fend runs on its own thread with an 8 MiB stack: about 7× headroom. Separately,
`9^9^9` was still computing after 5 s, since arithmetic is exact. fend's `Interrupt` ends it at the budget,
and the test sees it return within 50 ms. The crate unwinds, unlike the engine, so a panic in fend ends only
the worker thread and comes back from `join` as no answer.

**Locale.** fend has one locale setting, a point or a comma for decimals. It follows
`Locale.current.decimalSeparator`, so "1,5 + 2" is 3,5 where the Mac writes commas. Nothing else is translated.

**Linking.** A second Rust staticlib met two problems. SwiftPM copies every XCFramework's headers into one
`include/`, and two `module.modulemap`s at its top made "Multiple commands produce …/include/module.modulemap".
The calculator's headers therefore sit in `include/DockCalc/`, where clang finds a module map named for the
module. The engine is untouched. Both libraries' main objects define `rust_eh_personality` and std's
`EMPTY_PANIC` as strong external symbols. Every other Rust symbol is internal under LTO, as `nm` shows. The
linker keeps one of each without a word, and they are the same toolchain's identical code.

**The row.** It sits in its own section, ranked first and matched exactly, so it is the top hit unless a learned
pick outranks it. Its id is `calc` whatever the answer, so `RowsView` keeps one row while the query changes and
only its text moves. Its title is "= 57", or "≈ …" when fend says "approx.". It stands on a blue plate:
Clipboard History has orange, and gray is what a plugin without a tint gets. ↩ copies the answer without the
approximation. `ResultPayload.isLearned` keeps it out of learned picks, which would otherwise fill Settings →
Search with "= 57" for "33+24". It is the first toggle under Settings → Search → Sources.

## Observations

- Not seen live. The installed Dock2 was running, and another session was editing this checkout. Its
  half-done `PromptedPermission` change broke the build there, so the suite ran in a worktree at `HEAD`
  with only this change applied: 352 tests passed. A `DOCK2_DEBUG` run typing "33+24" and "1 lb to oz", then
  ↩, is still owed.
- Spotlight's answer row was not measured. Spotlight would not open from the shell beside Dock2, which holds
  ⌘space. The title form is **Open:** in the product.
- No currencies: fend asks its host through `ExchangeRateFnV2`. This is _Next_: rates fetched by dock2 (the
  ECB's daily reference rates are free and keyless), cached, and given to fend.
- fend reads `10 km / 2 h` as `(10 km / 2) h` and answers "5 km h". `5 ft 10 in` needs a `+`.
  "2024-10-24" answers 1990, and a phone number with dashes answers a negative number. Spotlight is believed
  to do the same with dates; that is unmeasured.
- fend's MIT licence wants its notice shipped with the app. dock2 has no third-party notices yet, and
  wasmtime's Apache licence asks the same.
