# The product, designed

> Change `1792478443` — 2026-10-19

## Goal

Write down what dock2 is for — a Dock that takes in Spotlight's search, the clipboard and, later, ⌘⇥ — and
settle first the questions that decide whether it can work: how far the Spotlight index can be used and
controlled; whether a dock revealed by the pointer can take typing; how summoning and number shortcuts can
be bound; what the panel above the dock should be. The design is `.agents/product/`.

## Implementation

Every claim the design leans on was tried on this Mac (macOS 27.0.1) in throwaway apps launched through
LaunchServices, so that each ran as its own unprivileged app — no Accessibility, no Input Monitoring —
driven by synthetic input from a process that refused to type unless an experiment's own window had the
keyboard.

**The Spotlight index.** `MDQuery` predicates give full control: "files but not apps" is
`kMDItemContentTypeTree != "com.apple.application"`, and kinds, folders and dates narrow further. The home
folder here holds 2.88 million indexed items, two Chromium checkouts among them, so a name query costs what
its selectivity costs: "receipt" 3.6 ms (17 results), "rec" 50 ms (20,141), "re" 233 ms (260,117), "r"
19.8 s (415,726); "rec" capped at 50, 14 ms. Hence no whole-index search below three characters. Of 439 app
bundles in the index, 239 are helpers under `/System/Library` and 108 build products in the home folder —
hence a catalog of dock2's own for apps. Usage data exists (Safari: `kMDItemUseCount` 69, per-day
`kMDItemUsedDates`), but only two non-app files had a last-used date in 30 days: files here are opened from
terminals and editors. Nothing apps donate privately came back — a 14,051-result full-text query returned
no item without a path, and no Mail, Notes, Messages, Contacts, Calendar or Safari content type matched —
and System Settings panes are not in the index at all.

The decisive finding came last. For an app without folder access, the index **silently withholds** results
inside Desktop, Documents and Downloads: a fresh app searching the exact names of a Desktop file and a
Documents file found neither, where the terminal found both, and no prompt appeared. A query *scoped* to
one of those folders raises the "would like to access files in your … folder" prompt — one per folder — and
a synchronous query blocks until it is answered; refused, the scoped query returns nothing. Hence the folder
grants in the first launch, and "no permission" stopping short of those folders.

**Typing into a revealed dock.** A non-activating `NSPanel` in an accessory app took the keyboard 13 ms
after `mouseEntered` called `makeKey()`. The editor in front kept the menu bar, typed keys landed in the
panel, and ordering the panel out gave the editor's window the keyboard back with no bookkeeping,
repeatably. It worked from a timer, with no user event, too: cooperative activation leaves non-activating
panels alone. While the panel had the keyboard, the editor's window resigned key.
`CGEventSource.secondsSinceLastEventType` gives the time since the last keystroke without any permission
(it saw the driver's, 0.26 s earlier): that is the typing guard. A global mouse-moved monitor saw the pointer
reach the bottom edge, also unprivileged.

**Shortcuts.** With Spotlight's shortcut on, a Carbon hot key on ⌘space fires *and* Spotlight opens, taking
the keyboard about 20 ms after dock2's panel had it: the chord cannot be shared. SkyLight's
`SLSSetSymbolicHotKeyEnabled`, entry 64, switches Spotlight's off live and session-wide — another process
read it as off at once — without writing `com.apple.symbolichotkeys`. With it off, ⌘space reached the
experiment alone; switched back on, Spotlight returned. Switched off by a process that was then `kill -9`ed,
it stayed off: the guard has to restore it. Entries 1 and 2 do the same for ⌘⇥. Holding ⌘ and pressing ⇥
twice reached only the experiment, no system switcher was drawn (no Dock-owned overlay window appeared), the
second ⇥ fired the hot key while the panel had the keyboard, ⌘'s release arrived in the panel as a local
`flagsChanged`, and `NSRunningApplication.activate()` brought the chosen app forward. All of it from the
unprivileged app.

**Number shortcuts.** ⌥1 registered as a global hot key never reached the editor: a global ⌥-digit takes
the chord from every app, and on many layouts those chords type brackets, braces and `#`. Rejected with it,
though it worked: a permission-free "hold ⌥" mode — ⌥ alone for 300 ms revealed the panel with the keyboard,
the digit arrived locally as "1" ignoring modifiers, and both a quick ⌥5 and ⌥ held after a recent
keystroke passed through to the editor as "∞". ⌘1–9 inside dock2 is simpler and collides with nothing.

**The clipboard.** The SDK documents a per-app pasteboard policy (`NSPasteboard.accessBehavior`, macOS
15.4) whose default for the general pasteboard is to ask on programmatic access. Here a fresh app reported
`.alwaysAllow` and read another process's text with no alert. The design reads the policy rather than
assuming either answer. The pasteboard was empty before the probe and was emptied after it.

**Spotlight on macOS 27** runs in `/System/Applications/Siri AI.app` (`com.apple.campo`; window owner
"Siri"): a 640 × 57 pt bar, 334 pt from the top of a 1243 pt screen, that grows downward to fit — 467 pt for
seven rows of 56 pt. "saf" gave Safari, Communication Safety, a Google bookmark, Lockdown Mode, Security
settings twice and Default web browser; a word it did not know put web pages above "Search in Finder".
Those numbers are the panel's starting point.

**The system Dock**, hidden, still exposes its tiles through Accessibility, each with `AXStatusLabel` and
`AXProgressValue`: the way to badges and progress. From an unprivileged app, `NSRunningApplication.hide()`
and `terminate()` work on another app with no prompt (`hide()` returns false, and hides anyway).

**Bario's plugin system** (`~/Developer/bario`) was read for lessons, not decisions. WasmKit cannot
interrupt a running call; a synchronous host import let one slow request cost an instance; re-entrant calls
crossed, and crashed, until a per-instance queue serialised them; its UI vocabulary displays and nothing
more — no lists, text input, focus or keyboard; and WIT was turned down because a UI tree is recursive. Hence
dock2's actor model (events in, effects out, never blocking, never re-entered) and its keyboard-first
components.

**Decided with the user**: clipboard history joins the MVP; ⌘space only, with ⌘⇥ designed for _Next_;
dock2 owns its auto-hide, and a Settings window starts with it; results grow upward; ⌘1–9, not ⌥.

## Observations

- Unverified, and marked **Open** where the design depends on it: whether the system's now-playing service
  answers dock2 on macOS 27; which hot key entries ⌥⌘D and ⌃F3 are, and whether they reveal the hidden
  system Dock; "minimize windows into application icon" as a takeover; whether the hot key table resets at
  logout; badges and progress with live values; whether iCloud Drive and external volumes prompt like the
  home folders; Stage Manager.
- The values the design names — the dwell, the typing guard, budgets, row counts, retention — are starting
  points, to be tuned in use.
- `NSPasteboard`'s detection APIs, refined for Swift, were not exercised.
- The experiments live in a scratch directory, not the tree. The probe apps' folder answers were reset with
  `tccutil`, and nothing they touched — the hot key table, the pasteboard — was left changed.
