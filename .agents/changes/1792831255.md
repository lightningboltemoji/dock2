# Settings in a TOML file

> Change `1792831255` — 2026-10-24

## Goal

dock2's settings lived in its defaults domain, `zip.tanner.dock2`, and its plugin choices in
`plugins.json`, neither of which a person can keep in a dotfiles repo, share between Macs, or read with
comments in it. emira already reads and writes `~/.config/emira/config.toml` with its own TOML 1.0 reader and
a writer that changes one value without disturbing the rest of the file. dock2's settings are flat, the
Settings window writes them, and the call sites were already behind one typed API, so the same strategy
fits. The plan and its decisions are in `PLAN.md`.

## Implementation

`Dock2TOML` is emira's `TOML.swift` and `ConfigDocument`, copied rather than shared, with a header naming
the commit; extracting a package later is moving the target. Changed: its own `TOMLError`, keys addressed by
path segments (plugin ids carry dots), a public reading API since the schema is another module, and an
insert that joins the nearest table the file wrote (as a dotted key where the tables between aren't
written) rather than always appending a header. A key inside an inline table can be changed but not added
or removed: that would mean rewriting the table. Arrays past 80 columns are written one element a line,
since `pinned` is written by dragging tiles and would otherwise be one long line in someone's file. The
vendored file keeps emira's long comments, so it still diffs against its source; the three-line rule in
`DOCS.md` is not applied to it.

`SettingKey` became a path, a default and a codec; one setting may be several keys (`FinderIcon`'s
picture, colour and fill). `SettingsStore` keeps its subscript and `observe`, so no consumer changed. It
holds the document in memory, applies a change at once and writes 250 ms after the first, re-reading the
file under a lock and replaying its own edits over whatever someone else wrote meanwhile. It writes through
a link: measured, `Data.write(options: .atomic)` at a symlink replaces the link with a plain file and leaves
the dotfiles copy untouched. emira has that bug.

Two departures from emira, because the file is shared between Macs running different builds: a key the
file gets wrong is a diagnostic and reads as its default rather than refusing the whole file, and dock2
never removes a line it doesn't understand, so an older build keeps a newer one's keys. A file that isn't
TOML still changes nothing; at launch dock2 runs on `config.last-good.toml` instead of nothing, since it is
the dock.

`fileAccess` and `askedToPaste` describe one Mac, so they are `SettingKey(machine:)`, kept in `state.json`
behind the same subscript. Rejected: a second store, which would have meant passing it to the dozen places
that read `fileAccess`. `onboarded` is in the file, so a second Mac skips the first launch; its file-access
question comes from Files, which already asks while the choice is `.notAsked`. Open at login is now the
file's `open-at-login`, applied to `SMAppService` at every launch, both ways.

Plugin choices are `[plugins."<id>"]`. Grants are kept as `revoked` rather than `granted` + `declared`:
`granting` computed exactly "declared now, less what was declared and not granted", so the list of what was
revoked carries the same decision and reads well by hand. One edge changes: a capability revoked, dropped
from the manifest and declared again stays revoked, where it would have been granted. Removing a plugin
keeps its table, since deleting it would put a copy still installed on another Mac back on its defaults,
every capability granted. A plugin failing five times a minute is now suspended in memory until dock2
quits, it is tried again from Settings, or new code is installed; writing `enabled = false` mixed up the
person's choice with dock2's, needed undoing on install, and would have switched the plugin off on every
Mac sharing the file.

The defaults domain is imported once, into each of the file and `state.json` only while it doesn't exist,
so a file another Mac wrote wins; open at login comes from `SMAppService`, so the first launch doesn't turn a
login item off. The property-list decoding moved verbatim into the importer. `plugins.json` is imported once
a Mac, per installed plugin the file says nothing of, a plugin switched off for failing coming back on.
Both old sources are left in place. Every process that opens the standard store imports first, so
`dock2 plugin` run before the new app can't create the file and preempt the import.

Also: `dock2 config path | open | check | explain | get | set`; Settings lists what the file gets wrong
above every section and opens the file from About; `config.example.toml` is generated from `Settings.all`
and pinned by a golden test (`make example`); `magnification`, `largeSize` and `position`, written and never
read, are gone; the violet default became `#6A5CD8` exactly, the eight-bit value the file writes, so the
example reads back as the defaults.

## Observations

- Not run live: the installed Dock2.app was running, and replacing it with the build takes over the dock.
  `make test` passes (341 tests), and `dock2 config` was run against a scratch file, importing this Mac's
  real domain correctly (the bit-13 ⌃ chord became `ctrl-cmd-v`, defaults were left out, `fileAccess` went to
  `state.json`). Still to see live: an editor's save applied, a slider writing once, the Settings banner, a
  symlinked file, a plugin suspended, onboarding pre-filled, open at login applied.
- Running `dock2 config` with a `DOCK2_CONFIG` that didn't exist created the real
  `~/Library/Application Support/dock2/state.json` from the domain. Harmless: it holds what the new app
  would have imported.
- The cask's `zap` lives in `lightningboltemoji/homebrew-tap`; it should leave `~/.config/dock2` alone, the
  person's own file. Not checked here.
- Empty tables are left behind: setting a table's only key back to its default leaves its header.
- A key added to a new table goes at the end of the file, after the plugins' tables if there are any.
- `searchSourcesOff` names sections by their titles, which is brittle across a rename; unchanged.
- A chord whose key has no name in the vocabulary (keypad keys, ISO §) can no longer be recorded, since the
  file couldn't spell it. One already in the domain is imported as `"none"`.
- Recording ⌘space as the summon chord now reads back as the Spotlight takeover rather than a chord macOS
  refuses.
