# Finder is an app

> Change `1794557908` — 2026-11-13

## Goal

The first tile stood in for Finder as well as opening Files. It wore Finder's running dot and badge, and Finder
could never have a tile of its own: `DockModel` dropped it from the pinned and running apps and refused to sideline it.
Once the tile was named the Files tile (`1794556735`), a Files tile carrying Finder's dot read as the two being mixed
up, and `AppDirectory.filesIcon` even fell back to whatever icon the user gave `com.apple.finder`. The user wants Finder
on the dock when it is open, and the Files tile to be dock2's alone.

## Implementation

`TileKind.files` has no app, so it shows no dot or badge, and ⌥-click opens Finder by name. `DockModel` no longer treats
Finder specially: it can be pinned, sidelined, or shown among the running apps. The Files tile's own icon is Finder's
own (`Entry.own`), and an `[icons]` entry for Finder applies to Finder alone.

Finder runs whenever the desktop does, so "running" alone would leave a Finder tile there for good. `DockController`
counts it as running only while `AppWindows` holds a window of its (`isOpen`), minimised ones included. That decides
its running tile, its dot and the puck. The test was measured in the `golden-gate-base` VM (macOS 27.2): with only the
desktop, Finder lists no `AXWindow`, and a Finder window is one (`FinderWindow`, standard). `windowsChanged` reshapes
the dock when Finder's openness changes, as it does when a window's tile comes or goes.

Finder's menu has no Quit or Force Quit. The system Dock's Finder menu, read in the same VM, has its windows, Finder's
own items, places, Show All Windows and Hide or Hide Others, and nothing to quit with.

Verified in the VM on the debug build:

- With only the desktop there was no Finder tile, and the Files tile had no dot.
- Opening a window added Finder, with its dot, after the running apps. Minimising it kept the tile, beside the window's
  own. Closing it took the tile away.
- Keep in Dock pinned `com.apple.finder`, and the pinned tile showed without a dot once the window closed. Clicking it
  opened a window, and the dot came back.
- ⌥-click on the Files tile opened a Finder window, and a plain click opened Files.

## Observations

- Without Accessibility, `AppWindows` sees no windows, so an unpinned Finder never has a tile and a pinned one never
  has a dot. Settings → Permissions now says so.
- A Finder window on another Space when dock2 starts is missed until a window changes, as for every app's menu (§16).
- Search still says Finder is Running and ranks it with the running apps, since it uses `RunningApps` alone.
- Sidelining Finder was not driven.
