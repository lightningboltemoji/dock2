# Views: the component tree, its renderer, "Show all…", feedback

> Change `1792498303` — 2026-10-20

## Goal

Roadmap step 6: one component vocabulary for every screen in the panel — the plugins' and dock2's own —
rendered once; the stack over the search; "Show all…"; the feedback the views spec lists.

## Implementation

**The tree is Core and Codable**, decoded in tests from the JSON a plugin would write, every kind round-
tripping, unknown kinds and icons refused. The list's filter lives on `ListNode` so it is tested with the
rest of matching.

**The list is search's rows.** `ResultsView` became `RowsView`, fed `RowModel`s by search and by lists
alike, so a list looks and keys like search with nothing drawn twice. The first "Show all 1,970 files…" lagged
about a second a keystroke — a view and an icon per row; the rows view now keeps views only for the rows
in sight and asks for icons as they come into sight, and filtering the section by "store" redraws within a
frame.

**Back from a view.** The search's session is kept while a view is open; putting the query back into the
field finds the same query and redraws it rather than searching again, so the results and the selection
are as they were — verified: "sett", ↑ to "Show all…", ↩, "store", Esc, Esc → "sett" with "Show all…" still
selected.

**The field's placeholder** did not change while the field was being edited: the field editor takes it as
editing begins. Setting it now begins editing again.

**Feedback**, verified on this Mac: Copy Path from ⌘K put the path on the clipboard, dismissed, and "Copied"
appeared where the field was and faded; Force Quit on a probe app asked in red, Esc kept the probe running
and the panel up, ↩ ended it and dismissed. The spinner was checked forced on — it sits at the trailing edge
as far in as the magnifier — since every query on this index finishes before a screenshot can catch it.
"No results for “qxzj”" shows as one row, and a list with nothing left says "No results".

## Observations

- Detail, form and grid have no host yet, so they have been built against the spec but not seen; the
  clipboard's history and the first plugins will be their first users.
- A grid does not scroll yet.
- Testing found a gap in the test tools, not dock2: restarting dock2 gives ⌘space back to Spotlight until
  the new instance takes it, and keys typed then went to Spotlight and opened a result, launching Xcode. The
  scratchpad's key tool now refuses while Spotlight is on screen.
