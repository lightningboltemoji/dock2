# A control socket, and a debugging dock2 to observe

> Change `1792564865` — 2026-10-20

## Goal

Watching the live dock2 kept going wrong. Revealing the dock meant moving the pointer, which took it from
the user while they worked. Typing meant posting key events: an Esc dock2 did not take interrupted the
session in the terminal, and keys posted to dock2's process without their characters never arrived. And
nobody knew where the field was on screen until it had been screenshotted. The user wanted a way to drive
dock2 without key combos, after emira's socket, and the method written down. They asked that anything as
strong as typing or reading the screen stay behind a flag set at launch, while the verbs any tool might
want, such as opening the dock, stay open to all.

## Implementation

**One binary, two ends.** `dock2 <verb>` is the running dock2's own executable: `main.swift` sends the
control verbs to `ControlCommandLine` before anything starts. The protocol (`ControlCommand`,
`ControlReply`, `ControlWire`, `DebugState`) is in Dock2Core and tested there. The socket (`ControlServer`,
`ControlClient`) is in Dock2System, since it needs no window. `ControlRouter` is in the shell, beside the
controllers it calls. The shape is emira's, JSON lines with the version read first and one request per
connection, simplified: there is no `watch` stream, because nothing here needs one yet.

**The gate.** `summon`, `dismiss`, `files`, `clipboard` and `status` go no further than the shortcut and
the dock's tiles. `debug state` reads the field's text and the rows, which can be clipboard entries and file
names. `debug type` and `key` type into dock2, and ↩ opens what is selected. So the router answers `debug …`
only when `DOCK2_DEBUG=1` was set at launch, and refuses it otherwise, naming the flag. A setting was
rejected for this: a setting is the user's and lasts, while a debugging dock2 belongs to whoever launched
it. Gating by build (a dock2 run from `.build`) was rejected too, since it would open the debug verbs on
every developer's everyday dock2.

**Keys without the window server.** `type` and `key` build `NSEvent` key events and send them through the
stage window, so they take the path a person's key does, the stage's `sendEvent` included. Esc in a view,
⌘ badges and the field editor see them as they see a real key, and nothing reaches another app. They need
dock2 to have the keyboard, and say so otherwise.

**Frames for the camera.** `DebugState` gives the field, the body (the glass as the panel wants it), the
reach (the most it grows to at that width) and the platter, in the coordinates `screencapture -R`
takes. `capture` and `record` are composed in the CLI from `debug state` and `screencapture`, with margins
for the shadow and the labels. A recording into an existing file fails ("Failed to save to final
location"), so the CLI removes the file first.

**Verified.** `ControlTests` (parsing, refusals, framing, the version message, the socket path) and
`ControlSocketTests` (an answer on the main thread, the socket removed on stop, a dead socket taken over,
a file at the path left alone, a live dock2 kept, a deadline ending only its own connection) pass. Live,
with `DOCK2_DEBUG=1`: `status`; `summon` then
`debug state`, its field at (960, 1184), 640 × 57, its platter at (1070, 1285); `debug capture field`. A run
was recorded in the background with `debug record reach 6`, then `debug type safari --every 0.12` (rows
Safari and the safari folders), `debug key escape` (empty and resting) and a second Escape (dismissed),
with no pointer or key from outside. A first run lost the keyboard within 0.3 s of each summon. The user was
using the Mac, and a click elsewhere dismisses dock2 by design. With their hands off it held. Also live:
`debug reveal on` (the dock up, no keyboard) and `debug capture dock`, `files ~/Desktop` (Files at the
Desktop) and `clipboard` (Clipboard History), each checked through `debug state` and a capture.

**Two bugs the live run found.** Connections were first kept by descriptor. Requests a few seconds apart then
failed with a broken pipe: a closed connection's 5 s deadline fired on the next one, which had reused its
descriptor. Connections are now kept by a count. `aDeadlineEndsOnlyItsOwnConnection` holds a second connection
quiet across the first one's deadline. It fails with the descriptor-keyed version and passes now. The second
bug was older: `dock2 files` from nothing with the dock away drew the field's magnifier and "Search" over
Files' path bar, with the capsule too. The entrance waits for the dock, and when it ran it faded the field
back in after the bar had taken its place. "Show in Finder" from another app with the dock hidden reaches the
same path. `enter` now fades the field in only when no bar holds its place.

## Observations

- `debug state` leaves out a frame or a screen that is not there, rather than writing null.
- Keys with modifiers (⌘K, ⌘1–9) cannot be sent yet: `key` takes the plain keys alone, and a chord would
  need `performKeyEquivalent`'s path rather than `sendEvent`'s.
- There is no `watch`: an agent waiting on something polls `debug state`.
- `summon` with a query sets the field's text at once, as a paste does; `debug type` is the way to see it
  typed.
- `.agents/OBSERVING.md` is how to use all this. It also keeps what synthetic input still needs, for the
  system Dock and the cases the socket cannot reach.
