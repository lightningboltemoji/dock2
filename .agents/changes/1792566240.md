# Releases from CI, the Homebrew casks, and Dock2.app

> Change `1792566240` — 2026-10-21

## Goal

dock2 had `make app` and `make notarize` but no way out of this Mac. The user wanted the GitHub build and
the tap that emira, bario and Ping already have, the same way they have it, and the bundle renamed
`Dock2.app`.

## Implementation

**The workflows are emira's.** `release.yml` is two channels: `main` replaces `dock2-tip.zip` on a `tip`
prerelease, a `v*` tag publishes that version once and bumps the `dock2` cask. `ci.yml` builds and tests
pull requests. They are emira's, which bario's matches line for line, with three differences. The first is
a toolchain step, since the plugins need rustup's `wasm32-unknown-unknown` target. The second is
notarization: emira notarizes inline with the Apple ID, a second copy of the steps its Makefile would
otherwise own. Here the job stores the notary credentials as a profile in the throwaway keychain it
imports the certificate into, and runs `make notarize`; `NOTARY_KEYCHAIN` is the one variable the target
gained, because `notarytool --keychain-profile` otherwise looks only in the login keychain. Storing the
profile validates it, so bad credentials fail before the build. The third is comments cut to `DOCS.md`'s
length. The tap's token comes from the `update-tap` app, as in the other repos. The user set up the
`production` environment (`main` and `v*`, the two `TAP_APP_*` secrets) during the change. It matches
emira's, bario's and Ping's exactly.

**Cargo is not cached.** A clean checkout, built here, took 60 s for the engine (wasmtime, LTO), 5 s for
the plugins and helpers, and 26 s for `make dist`. That is small next to the 4–7 minutes
emira's release job takes, and a cached `target/` would be one more thing that can serve a stale build.

**`Dock2.app`, and only the file.** `BUNDLE_NAME` is the bundle; the executable, the archive
(`dock2-<version>.zip`) and `CFBundleName` stay `dock2`, as bario's do. As measured,
`FileManager.displayName` and `localizedName` give `dock2` for `Dock2.app` and `bario` for `Bario.app`, so
Finder and Spotlight show `CFBundleName`, not the file name. Bario's Makefile says otherwise, and its
comment was not carried over. Nothing in the code keys on the path; every "am I the bundle" check reads
the bundle identifier.

**The CLI through the cask's link.** The cask puts `dock2` on `$PATH` with `binary`, a symlink into the
bundle. Run that way, `dock2 --version` said `dev`: `Bundle.main.executableURL` is the link's path (as
measured, even when found through `PATH`), and `Bundle.main` finds no bundle beside it. emira's and bario's
installed CLIs say `dev` the same way. For dock2 it is worse than a version string: the settings' domain,
the built-in plugins' folder and the key store are each chosen by `Bundle.main`, so `dock2 --restore`
from `$PATH` would have run as a development build. `main.swift` now execs the real path when the
executable is a link into dock2's own bundle (`Dock2Identity.bundledExecutable`, tested against a fake
bundle). Fixing each `Bundle.main` read instead was rejected: there are seven of them, and the next one
would be missed. A wrapper script in the bundle would hit the same problem one level down, since its `$0`
is the link too. `realpath` rather than `resolvingSymlinksInPath`, which strips `/private` and would give
a path that differs from the one it was given, for an executable that is not a link at all.

**The casks** are bario's and emira's shape: `0.0.0` placeholders until the first tag, `dock2@tip` on the
permalink, `conflicts_with` each other, arm64 and Tahoe, quarantine stripped. Their uninstall adds
`dock2 --restore` after `quit`. Quitting releases everything (`applicationWillTerminate`), but a dock2 that
died leaves its journal for the guard or `--restore`, and once the cask is gone there is no `--restore`
left to run. `must_succeed: false`, because an uninstall the user asked for should not stop on a restore
that has nothing to do. `zap` takes `Application Support/dock2`, the preferences and `Logs/dock2`; Homebrew
runs it after the uninstall directives, so the journal outlives the restore. Both pass `brew style` and
offline `brew audit`, run from brew's own clone of the tap and removed again.

## Observations

- The workflow has not run. The build steps were run here from a clean worktree; the runner's image,
  rustup on it included, was not.
- The cask's uninstall was not run against a live `Dock2.app`: a development dock2 was in use the whole
  time. The quit Apple Event reaching `applicationWillTerminate` is inferred from AppKit, not seen.
- `brew audit --online` on `dock2` fails until `v0.0.0` is replaced by a real tag's bump, and on
  `dock2@tip` until `main` is pushed and `tip` exists.
- The notarization path (`make notarize` with `NOTARY_KEYCHAIN`) is untried, as it is in
  emira: no Developer ID exists for either.
- `.gitignore` lists `Resources/Info.plist`, which is tracked, so the line does nothing.
