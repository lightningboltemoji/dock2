# The sheet

> Change `1793765159` — 2026-11-03

## Goal

The third step of the capabilities plan (`design/plugins.md`). Installing from Settings showed an `NSAlert`
listing what a plugin would reach, with no reasons and no way to say no to one capability while keeping
the rest. A first-party plugin switched on held everything its manifest declared without being shown it.
The product's [asking](../product/plugins/permissions.md#asking) wants a sheet with a switch per capability.

## Implementation

**One model, two faces.** `PluginAsk` (Dock2Plugins) is what is asked. It has a row per capability: dock2's
lines, the plugin's reason, a note where macOS's own prompt may follow, whether it is full trust, and a
switch. It is built against the reach last agreed to. New rows are what `Reach.beyond` names, everything the
first time, and each switch starts as `PluginChoices.startsRevoked` says: off for a `*` command, and for
`query` while results start off. The rest are `unchanged`, shown as the person's choices stand. Settings
draws it as a SwiftUI sheet. `dock2 plugin install` and `dev` print it (`text(name:)`), ask once, and keep
each switch's starting state: what starts off stays off, for Settings to switch on.

**The answers come first.** `PluginStore.install(_:decisions:)` copies the folder in, reads the store again,
then writes each new capability granted or revoked (`agree`) before the host starts tiles. `query` carries the
results switch with it. A first-party plugin switched on for the first time on this Mac shows the same sheet
before anything is written. `PluginHost.switchOn` writes `enabled` and the answers in one update.

**The reach agreed to** is kept per Mac in `PluginData/<id>/agreed.json`, beside `commands.json`. It answers
two questions: whether a first-party plugin was ever asked about here, and what an update reaches beyond.
The config file cannot answer the first: switching a first-party plugin off writes nothing, since off is its
default and a key back at its default is taken out. A flag among the machine settings could hold "asked"
but not the reach. An installed plugin with no file yet is taken to have agreed to what it has installed.
`dock2 plugin dev` now asks on the store's record rather than its own memory of the last build, so a
terminal restarted mid-session no longer asks again for what was already agreed.

**Settings → Plugins** shows dock2's lines under each switch, then "<Plugin> says: “…”" in a caption. A
`run` whose commands include a full-trust one carries a warning sign. The results switch shows `query`'s
line and reason.

The sheet sits on the "Install from a Folder…" section alone: a `.sheet` on a `Group` is copied to every
child, which would present it once per plugin. It sizes to its rows, up to 640 points.

Seen in a debug run on a copy of the config: Now Playing switched on through Accessibility raised the sheet
(icon, "by Dock2 · Comes with Dock2 · Version 1.0.0", its line, "Now Playing says: …", Cancel and Turn On),
the config file unchanged while it was up. Cancel left the switch off and no `agreed.json`.
`dock2 plugin install` on a plugin declaring `local-network`, writable `files` and a `*` command printed every
row, both macOS notes, both commands as full trust, and "Off until you switch it on", and installed nothing
on "n".

## Observations

- "Install from a Folder…" through `NSOpenPanel` was not driven: the sheet it raises is the same view, built
  the same way, tested as a model in `PluginHostTests`.
- An update's sheet ("This version also asks to", then "As before") was seen only as the CLI's text.
- A first-party plugin that a new dock2 makes reach further asks nothing while it is on, since there is no
  install. `agreed.json` holds what that check would compare against.
- The CLI's `--yes` agrees to every switch as it starts, `*` commands off, the same as answering "y".
