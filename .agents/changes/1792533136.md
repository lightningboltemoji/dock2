# Reviews of the old code and the new, and the product's gaps, second pass

> Change `1792533136` — 2026-10-20

## Goal

Three reviews ran over the code: one of the night's later work, one of the oldest — the takeovers, the
guard, the keyboard, the dock — and a second audit of `product/` against the code. Between them they found
eleven defects in the new code, seven in the old and thirteen gaps from the design. The worst could leave
the user's Dock hidden for good: a give-back that did not take still deleted the journal, `--restore` then
had nothing to give back, and the next launch journaled dock2's hidden Dock as the user's own.

## Implementation

**Takeovers.** `restore` reads back what it wrote and says whether it took; `release` forgets only what did,
so the guard, `--restore` (exiting 1) or the next run tries the rest again. A known takeover with no
journal entry whose *mark* the system shows — a state only dock2 leaves — is recovered rather than
snapshotted: the Dock's reveal delay of 1000.0625 (not 1000, which the common "hide the Dock for good" tip has users
type; auto-hide alone is no mark either: it may be the user's),
`NSFileViewer` naming dock2, and a hot key off in the window server's table while `com.apple.symbolichotkeys`
leaves it on. That last was checked read-only on this Mac: every entry the user switched off in the
preference (15–26, 60, 61, 164) is off in the table, every one on is on, and 64 and 65, absent, are on.
An unreadable journal is set aside, not deleted; a newer dock2's entries are kept. The reviewer thought
LaunchServices' list of running apps went stale without the run loop; a probe launched mid-sleep showed it
does not, but a Dock launchd has just started is in the process table before it checks in, so the restart
looks there too. Checked: `kill -9` gives everything back; SIGINT the instant the Dock hides leaves a Dock
started after the give-back. Recovery was not run against the real Dock: losing the journal by hand would
cost this user their own auto-hide, which is the guess recovery makes.

**Dock and keys.** The dock composes only the apps it can draw, once each, so the numbers, the ring and a
drag's gap all count the same tiles; a pin lands before the gap-th shown app in the full list, keeping
uninstalled ones pinned out of sight. A press follows its tile across a relayout. A tile drag is judged off
the dock by where it ended — a drag Esc cancels reports no operation either. Settings goes through one
`handOver` from every path. ⌘↩ and ⌘K stop at a view that does not claim them.

**The new code's review.** Number settings save whole numbers ("5", which Bitwarden reads, not "5.0"); the
watcher's first read touches the pasteboard but keeps nothing, since who copied it is unknown; a clear wins
over a load in flight; secure settings are read off the main thread and plaintext ones migrate; images are
compacted off it; launchers fail the document allowlist; Full Disk Access is probed once a second at most.

**The product's gaps.** One rule, `FileAccess.isClosed`, for Files' locks, search's near places and the
preview's count, so choosing Full Disk Access before the grant raises no folder prompt. "Show all…" lists
search's own results. A copy's text — 2,000 characters, folded, punctuation as spaces — is kept in the sealed
index and matched as a scan; the history view filters as its owner by the same `ClipHistory.matches`. That
exposed a field bug every owner-filtered list had: each update re-began editing to refresh the placeholder,
which selects the text, so the next key replaced it. The note stands alone after "No results"; Open in
Finder opens the folder; the ringed tile is announced and the field is a search field; Permissions shows
Paste from Other Apps, its anchor `Privacy_Pasteboard` read from the Privacy extension's resources and
opened once to be sure; a cold-launch reveal waits for dock2; auto-hide slides at the copied speed; every
action that opens no view dismisses; a plugin view summons dock2 only in answer to the user; Open is always
on a tile's menu.

**A review of these fixes.** Dock2 wrote the very 1000 s the "hide the Dock for good" tip has users type, so
recovery at every launch would have mistaken such a user's hidden Dock for dock2's and given it back unset:
dock2 writes 1000.0625 now, exact in binary so that it reads back equal. A recovery that could not be
written left its entry only in memory, and a take-over on it no journal on disk for the guard: `engage`
writes the journal first in that case too, and the guard recovers marks even with no journal file. An
accepted drop is never off the dock: the drop's own relayout could shrink the platter from under its end
point. A plugin tile's click whose view came from a network response lost the view, the response not being
an action: the host follows cause now — a request made in answer to the user, and its answer, answer the user
too, within 10 s, a starting value, unless the user has dismissed dock2 or gone to another app since — for
views and `open` alike. A placeholder that changes while text is typed waits for the field to empty, since
re-beginning editing would select the text. The crash path was run again with the new
value: the journal held the user's own auto-hide and unset delay, and the guard gave both back.

## Observations

- The hot key's mark assumes Keyboard Shortcuts writes `com.apple.symbolichotkeys` when the user switches
  Spotlight's shortcut off; the table agreed with the preference for every entry, but the switch itself was
  not flipped to watch it.
- Recovering the Dock without its journal leaves auto-hide unset, whatever the user had.
- The hot key's mark would also match a tool that switched Spotlight's entry off in the table alone, writing
  no preference; dock2 would turn it back on. None is known to.
- A Dock at 1000 s from a build before the mark changed is not recognised; no such build left this Mac.
- Not seen on screen: a cold-launch reveal (it needs the bundle as the file viewer, and dock2 and its guard
  both dead). Seen, with a missing app and a probe pinned first: ⌘2 opened the probe, the second tile drawn;
  a drag Esc cancelled over the dock left the probe pinned in place, where the same drag uncancelled moved
  it after Chrome, the missing app keeping its place; the last tile pressed while a pinned app was taken
  away survived the shrink, and its release clicked the tile the press began on. Seen too: Settings from
  search comes forward with the keyboard; the field's search subrole; Permissions; clipboard search and the history's
  filter by a word past the first line; the note after "No results" under `DOCK2_FULL_DISK_ACCESS=off`;
  Open on a running app's menu; a platter click summoning dock2.
- A click that closes a tile's menu over the platter also reaches the platter, and summons dock2; whether the
  system Dock passes such a click on was not measured.
