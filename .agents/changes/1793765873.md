# `run`: the commands a plugin declares

> Change `1793765873` — 2026-11-03

## Goal

The fifth step of the capabilities plan (`design/plugins.md`). A plugin that wraps a command-line tool had
no way to run it. The product's [commands](../product/plugins/permissions.md#commands) let the manifest, not
the code, say what may run. The program must answer to macOS for itself rather than with dock2's grants.

## Implementation

**Asking.** `run(request, command, values, args?, stdin?)` names a declared command and its slots' values.
The host holds it under `run` at once, as a `RunningCommand`, so a revoke or a `cancelRun` that comes while it
is still spawning ends it as it spawns. Off the main thread, `CommandGuard` fills the slots. The folders are
those the plugin's folder settings hold, so a path or a folder lies inside one, resolved. `SecStaticCode`
checks the program against its `team`, before each spawn. Both read the file system and the check hashes the
program, which the main thread should never wait on.

**Spawning** (`PluginProcess`). `posix_spawn` with:

- `responsibility_spawnattrs_setdisclaim`, in `Disclaim.swift`, looked up by name, and without it `run`
  runs nothing.
- `POSIX_SPAWN_CLOEXEC_DEFAULT`, so the child holds no descriptor of dock2's but its pipes: not the control
  socket, the instance lock or the journal.
- `SETPGROUP` to a group of its own, signals at their defaults, and an empty mask.
- `PATH`, `HOME`, `LANG` and `TMPDIR` from the environment dock2 was started with (`LaunchEnvironment`, since
  dock2 empties its own), and nothing else.
- The working directory: the `{folder}`, else home.

stdin is the plugin's bytes, written off the main thread with `F_SETNOSIGPIPE`, so a program that exits
without reading cannot raise SIGPIPE in dock2. Without stdin it is `/dev/null`.

**What comes back.** stdout and stderr are read on a queue of the process's own and come back as `output`
events, base64, as they arrive. Past 4 MiB (`outputLimit`) the rest is read and dropped, so the program never
blocks on a full pipe, and `exited` says `truncated`. `exited` comes once the process has ended and both pipes
are read. It carries the status or the signal, and `timedOut`.

**Ending.** The group gets SIGTERM, then SIGKILL two seconds later, on a revoke, a stop, `cancelRun`, or the
time limit: the command's `timeout` within dock2's 60 s (`runLimit`). When the program exits on its own, what it
left in its group is killed while it is still a zombie, so the group id cannot yet belong to anyone else.
After a second the pipes are let go, in case something that left the group holds them. A signal is only sent
before the process is reaped, since after that its pid may be another's. A dispatch process source made for
a child that has already exited fires all the same (measured), so a fast program's exit is never missed.
A running process keeps the instance loaded, as any held resource does.

**Measured.**

- A child spawned through `PluginProcess` is its own responsible process
  (`responsibility_get_pid_responsible_for_pid`, in a test). Spawned plainly from the same test, a child
  answered to the terminal at the top of its parents (pid 20014 here).
- The requirement `anchor apple generic and certificate leaf[subject.OU] = "<team>"` passes `codesign -R` for
  a Developer ID app on this Mac (`ares.app`, L4BF7MF6UH) and fails for another team. `/bin/ls` named with a
  team is refused.
- The tests run `/bin/echo` with `hi; rm -rf ~` as one argument, a declared `/bin/sh -c pwd` in its `{folder}`
  with only the four variables and `sh`'s own, `/bin/sleep` past its half second, `/usr/bin/yes` to 4 MiB
  and its time limit, and `/bin/cat` reading what the plugin gave it.

## Observations

- If dock2 dies, its children are not killed: macOS has no parent-death signal. Each is in a group of its
  own and ends on its own time, past dock2's limit.
- A program that calls `setsid` leaves the group and is not killed with it.
- The team is checked with the static code before the spawn. A binary swapped between the check and
  `posix_spawn` runs unchecked, but it runs disclaimed, so without dock2's grants.
- Output is delivered per read, up to 64 KiB an event, uncoalesced. A chatty program costs one plugin call per read.
