# `dock2 quit`

> Change `1793683175` — 2026-11-02

## Goal

A session observing dock2 has to replace the running one with its own build. The only way from a terminal
was `kill -TERM`, which an agent's permission checks can refuse as interfering with a running workload, and
which says nothing about when dock2 has finished giving the Dock back. Quit was already in the dock's menu,
in search and in Settings, but not on the control socket.

## Implementation

`ControlCommand.quit` is one of anyone's verbs, not a `debug` one. It does what the Quit a click reaches
does, and it has to work on the dock2 that is running, which was usually not started with `DOCK2_DEBUG=1`.

The router can't terminate inside the handler: the reply is written on the socket's own queue after the
handler returns. So it schedules `NSApp.terminate` on the main loop's next turn. By then the reply is queued,
and `applicationWillTerminate`'s `ControlServer.stop` does a `queue.sync`, which runs after it. The reply
always gets out before the socket closes.

The CLI does not return on the reply. It waits up to 15 s for `InstanceLock` to be free. That covers
dock2's own release in `applicationWillTerminate` and the guard, which takes the lock as dock2 exits to
check the journal. `quit && .build/debug/dock2` then never meets "already running". `InstanceLock.awaitFree`
shares `claim`'s loop, but closes the descriptor at once without writing its pid, so `holder` keeps naming
the last real owner.

Measured on this Mac, with Settings open: `dock2 quit` returned 0 in 0.08 s, with dock2 and its guard gone.
The log said "gave back the system Dock and every takeover", `takeovers.plist` was removed, `autohide-delay`
was out of `com.apple.dock`, and `SLSIsSymbolicHotKeyEnabled(64)` was true. Launched straight after a quit,
the next dock2 claimed the lock, put its mark back on the Dock and journaled it, while the Dock was still
restarting from the give-back.

## Observations

- A dock2 built before this refuses `quit` with a raw `DecodingError`, not "another build": every build
  from source is version `dev`, so the version check can't tell them apart. `OBSERVING.md` says to
  `kill -TERM` such a dock2.
- The 15 s bound is far above the 0.08 s measured, so it only matters for a dock2 that hangs in teardown.
  Then the CLI says it is still quitting, names the holder's pid, and exits 1.
- No test covers `awaitFree`: `Paths.lock` is the real lock, which a running dock2 holds.
