# `network`'s additions, `local-network`, `apps`

> Change `1793766656` — 2026-11-03

## Goal

The last step of the capabilities plan (`design/plugins.md`):

- `network` reached only named HTTPS hosts and answered whole. An LLM client wants a streamed answer, a
  chat client a WebSocket, a feed reader any host.
- Nothing reached this Mac or the local network: Ollama on `localhost:11434`, a NAS, the Docker socket.
- `open` refused anything but a web page or a document, so a plugin could not open a note in Obsidian or a
  file in Zed.

## Implementation

**`network`.**

- `*` among the hosts reaches any HTTPS host (`RedirectGuard.mayReach`), redirects too.
- `http` with `stream` answers through a per-task `URLSessionDataDelegate` (`StreamedResponse`): the status
  and headers as an `httpPart`, the body in `httpPart`s as it arrives, then the `http` event without a body.
  A part reaches the plugin only while its request is held. Its end is the answer, so revoking `network`
  mid-stream cancels the task and the plugin hears that it was revoked.
- `webSocketOpen`, `webSocketSend` and `webSocketClose` drive a `URLSessionWebSocketTask` (`PluginWebSocket`),
  `wss` only, to a host the plugin names, eight to a plugin. It is held under `network`: a revoke cancels it.
  `webSocketOpened`, `webSocketMessage` and `webSocketClosed` follow, the last once however it closes. A
  plugin's own close is heard as `webSocketClosed`. The socket hands itself to its callback, so a reopened
  id never takes the old one's news.

**`local-network`.**

- `http` to a plain `http:` URL, or with a `socket`, needs `local-network` rather than `network`: `needs`
  decides by the URL's scheme. The host and port must be one the manifest names, a `$setting` read as a URL
  or `host:port`, and local by spelling. A socket must be one it names, `~/` expanded.
- The client is dock2's own (`LocalHTTP`): `URLSession` has no Unix sockets, and one path for both keeps
  App Transport Security out of plain HTTP to the LAN. One request a connection, `Connection: close`. The
  plugin's headers go as written, except those dock2 writes (`Host`, `Content-Length`, `Connection`,
  `Transfer-Encoding`). A header holding a line break or a colon in its name is refused.
- The answer is read by `HTTPResponseParser` (Core) as it arrives: a 1xx passed over, then by
  `Content-Length`, chunked, or to the close; no body for HEAD, 204 or 304. A whole answer is capped at
  16 MiB; past that the plugin should stream. Thirty seconds of silence ends it.
- Once connected over TCP, the address it reached must be loopback, private or link-local. A name that
  resolves to the internet is refused there, whatever its spelling.
- A redirect is the answer, never followed.
- `NSLocalNetworkUsageDescription` now names plugins, since macOS's prompt names Dock2.

**`apps`.**

- `open(url, app?)` needs `apps` when it names an app or a scheme that is not `http`, `https` or `file`, and
  still only in answer to the user.
- `PluginHost.opening` decides, without opening anything, so it is testable. A web page or a document opens
  as before. A link opens if its scheme is declared and the app macOS would open it in is not one that runs
  what it opens. A file opens in a named app if the app is declared, not a runner, on this Mac, and the file
  exists.

The failures the plugin hears from files, processes, the local client and `opening` are one type,
`PluginFailure`.

Tested against servers of the test's own: a POST with a query, a header and a body to `127.0.0.1` echoed
back; a chunked answer streamed as its head and two parts; a GET over `/tmp/dock2-test-guest.sock`; a port it
does not name and `http://example.com` refused; a stream revoked partway told so; a WebSocket opened,
echoed and closed once against a Network.framework echo; `ws://` and an unnamed host refused; and `opening`
for every case above.

## Observations

- Streaming over HTTPS and `wss` WebSockets were tested through their delegates against plain loopback
  servers. The host's own TLS-only paths were tested for refusals, not against a real TLS server.
- Local Network's prompt was not seen: the debug build runs as the terminal it was started from, which
  macOS does not ask about. A LAN address was not reached; the tests use the loopback.
- An answer's parts are delivered as they arrive, uncoalesced.
- WebSockets are `network` only. `ws://` to the local network, as Home Assistant speaks, is not offered.
- `local-network` has no HTTPS; a device with a self-signed certificate is out of reach.
