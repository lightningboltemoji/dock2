# First-party plugins start off; Bitwarden lists only Sign In while signed out

> Change `1792560881` — 2026-10-20

## Goal

Now Playing and Bitwarden ship inside dock2, and both started switched on: Now Playing's tile went on the
dock and its commands into Commands, and Bitwarden's Search Vault, Lock and Sign Out showed in Commands for
everyone, signed in or not. The user wants neither on by default, and Bitwarden to offer nothing but Sign In
until it is signed in.

## Implementation

**Off by default.** `PluginChoices.first` takes `enabled`. `PluginStore.reload` gives a first-party plugin
seen for the first time `enabled: false`. It still holds what its manifest declares (`query` only if its
results start on), so switching it on in Settings → Plugins needs no second ask, and Settings lists its
grants while it is off. A plugin installed from a folder still starts on, since installing it was the
user's choice. Choices already saved are kept: a Mac where a plugin was on keeps it on.

**Commands that follow the plugin's state.** Commands came straight from the manifest, so a plugin could
not change them. Two pieces were added:

- A manifest command may be `"hidden": true`: left out of Commands until the plugin lists it.
- A new effect, `setCommands { shown: [ids] }`, names which of its declared commands Commands lists, until
  the plugin says otherwise. The host warns about ids the manifest does not declare and drops them. The
  store keeps the list in `PluginData/<id>/commands.json`, so Commands is right before the plugin's next
  start. Removing a plugin removes its data folder, and the list with it. `PluginCommandsSource` reads
  `store.commands(of:)`.

The list is the plugin's state, not the user's choice, so it is kept out of `PluginChoices` and
`plugins.json`. Sending the whole list, rather than show or hide one command at a time, makes the effect
idempotent: a plugin can send it again at every start to correct what was saved.

Two other designs were considered. A manifest condition (`"when": "signedIn"`) would need the host to know
each plugin's state, which only the plugin does. Changing a command's title in place (Search Vault becoming
Sign In) would give one id two meanings in learned picks and frecency.

**Bitwarden.** The manifest adds `sign-in` (Sign In to Bitwarden, a view) and marks `search`, `lock` and
`sign-out` hidden. `handle` runs the event (the old body, now `step`), then, once the secrets and storage
have loaded, works out the commands for the state the event left and sends `setCommands` if they changed:
`["sign-in"]` with no session, `["search", "sign-out"]` while locked, and all three while unlocked. Hiding
Lock while locked goes beyond the ask, on the same principle. Doing this after every event rather than at
each transition catches every path, including a refused refresh token signing out, a lock timeout, and a
session that was deleted while dock2 was not running. `sign-in` runs the same code as `search`, which shows
the login form, the unlock form or the vault as the session requires.

**Verified.** `make test` passes. Added tests: first-party plugins start off holding their grants; a
hidden command waits until the plugin lists it, an undeclared id is dropped, and the list survives into a
new store; the effect round-trips as JSON. Bitwarden's flow tests check the list after loading, after
signing in, after locking, and after a refused refresh. Live, on the debug build:

- `dock2 plugin list`, run against an empty `plugins.json`, listed both plugins "off, comes with dock2".
  The user's own `plugins.json` was moved aside for that run and restored byte for byte.
- With the user's choices (Bitwarden on), typing "bitwarden" showed only Sign In to Bitwarden under
  Commands.
- Running Sign In opened the "Sign in to bitwarden.com" form. The real module sent `setCommands`, and
  `commands.json` read `["sign-in"]`.

## Observations

- This Mac's `plugins.json` still has both plugins on, saved before this change. They have to be switched
  off in Settings → Plugins to see the new default here.
- The signed-in lists (Search Vault, Lock, Sign Out) were checked in the plugin's tests, not live: that needs
  a real sign-in, which is still untried against Bitwarden's servers.
- Now Playing's Play/Pause, Next and Previous still show whenever the plugin is on, even with nothing
  playing. It could use `setCommands` too.
- A dock2 older than this skips `setCommands` with a warning, since effects are decoded one at a time, and
  ignores `hidden`, so it lists every command. Nothing has been released, so the interface version stays 1.
