# Files: the column browser, its operations, the ways in

> Change `1792500989` — 2026-10-20

## Goal

Roadmap step 7: Files, a column browser in the panel that stands in for Finder's windows — columns,
preview, the path bar, two tabs, copy and move with conflicts, progress and undo, drag and drop, ⌘F,
access, and every way in, "Show in Finder" among them.

## Implementation

**Measured first.** A Finder window on a scratch folder in column view, read through Accessibility and a
screenshot: 246 pt columns, rows on a 22 pt pitch 6 pt down, the icon 16 pt at 17 pt, names 13 pt at
37 pt, selection inset 10.5 and 10 with radius 6, accent in the focused column and grey in the rest.
Opening it changed only Finder's recent folders, which were put back from a backup and diffed clean.

**Screens.** The panel's view stack became a stack of screens, each with a size and optionally a bar in
the field's place; views built from nodes are one kind and Files another, so the stack, Esc and the
glass's growth are written once. Files opened from nothing dismisses on Esc instead of returning to an
empty field.

**One spelling for a URL.** Three bugs came from the same place: `contentsOfDirectory(at:)` resolves
`/tmp` to `/private/tmp` (checked: `file:///tmp/claude-501/` listed as `file:///private/tmp/…`), a
folder's URL gains a trailing slash once the folder exists, and `deletingLastPathComponent` adds one. The
selected folder lost its highlight, a new folder's rename never began, and a pasted item was revealed in
a column of its own. Listings now build URLs from the folder's own, and every URL entering Files'
state, its listings and the operations' results is `canonical`.

**A rename survives the watcher.** A new folder fires its parent's vnode source; the full reload that
followed took the cell being edited away. A column now reloads only changed rows while renaming, and a
listing that adds or removes items waits until the rename ends.

**Spring-loading** never came through `NSSpringLoadingDestination` on the table subclass — `NSTableView`'s
own drag handling never asks — so the column times the hover itself with the system's delay
(`com.apple.springing.delay`, 0.5 s here).

**Clones.** `copyfile` with `COPYFILE_CLONE | COPYFILE_RECURSIVE` cloned a 300 MB file's folder in 1.1 ms,
against 124 ms for a plain copy.

Verified on this Mac, in a scratch folder: a typed path completed part by part; ⌘C ⌘V into a subfolder;
the same again raising the inline question, ↩ giving "a 2.txt"; ⇧⌘N named in place, two ⌘Z taking the
name and the folder away; ⌥⌘⌫ confirmed in red; space's Quick Look; ⌘T and ⌃⇥ with the chip; a drag
onto a folder moving the file and ⌘Z moving it back; a held drag opening the folder; a slow click
renaming; ⌘F finding the subfolder's files by walking; "Show all…" for "sett" searching the Mac; Show in
Files from a result and Esc back to it; the Finder tile's click and its progress bar (forced on once).

## Observations

- Testing found the key tool's interlock wanting, not dock2: a restart hands ⌘space back to Spotlight for
  a moment, and keys typed then went into Spotlight's panel, opened a result and launched Xcode, which was
  left for the user since quitting it was not permitted; a ⌘K test through a quit probe's shorter menu
  pinned the probe, and was unpinned. The key tool now refuses while Spotlight is on screen, and the
  restart waits for ⌘space to be dock2's.
- Not seen yet, since dock2 run from a terminal has Full Disk Access and no bundle: the lock rows, search's
  access row, the "Show in Finder" takeover. A drag held over Finder's tile was not tried.
- Errors are toasts, not words on their rows; the chip has no ring.
