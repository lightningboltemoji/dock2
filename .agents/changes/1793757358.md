# Trusting the tap before bumping the cask

> Change `1793757358` — 2026-11-03

## Goal

The `v0.3.0` release published its archive and then failed at "Bump the Homebrew cask", which left the `dock2`
cask at 0.2.0. `brew bump-cask-pr` stopped with `Refusing to load cask lightningboltemoji/tap/dock2 from
untrusted tap lightningboltemoji/tap`. `v0.2.0` had run the same step on 2026-10-25 and passed.

## Implementation

Homebrew 7.0.11, released 2026-10-26, added `Limit implicit item trust to install commands` (Homebrew/brew
#24352). Before it, a fully qualified name in `ARGV` (`lightningboltemoji/tap/dock2`) made the item trusted
for any command. Now only `install`, `reinstall` and `upgrade` do that. Every other command needs a trust entry
already in place, so `bump-cask-pr` and `audit` refuse the cask. The `v0.2.0` run was on runner image
`20261023` and the `v0.3.0` run was on `20261026`, so the image's Homebrew changed between the two.

The step now runs `brew trust --tap lightningboltemoji/tap` after the clone. It trusts the whole tap, not just
`--cask …/dock2`, because the job clones the tap in order to commit to it, and so audit can read `dock2@tip`
and anything else in the tap without hitting the same refusal. The trust store is the runner's
`~/.homebrew/trust.json`, which goes away with the runner.

Rejected: `HOMEBREW_NO_REQUIRE_TAP_TRUST`. It is deprecated, and Homebrew says it will be removed. `brew tap`
grants no trust either, so fiber's `brew tap` in place of a clone fails the same way.

Verified locally with Homebrew 7.0.11 and a fresh trust store (`XDG_CONFIG_HOME` pointed at a temp directory).
`bump-cask-pr --dry-run` on the cask gives CI's exact error. After `brew trust --tap`, it and `brew audit` pass.
`brew style` passes either way because it lints the file without loading it.

## Observations

- Re-running the failed `v0.3.0` job won't help: a re-run uses the workflow as it was at the tag. The 0.3.0
  cask (`sha256 0870bb40d8d7b1d0ddb9dbd3c9afb1899baf56a4a4dd4dff2418f6d3d2cb3f8b`, GitHub's digest of
  `dock2-0.3.0.zip`) has to be bumped by hand. The next tag picks up the fix.
- bario, emira, Ping and fiber all have this step, and all their last tag releases ran before 7.0.11. Each one
  fails on its next tag until it gets the same line.
- The CI path has not been run end to end. The first proof is the next `v*` tag.
