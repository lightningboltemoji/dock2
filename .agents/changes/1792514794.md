# Release pass, begun: accessibility, the bundle, Show in Finder

> Change `1792514794` — 2026-10-20

## Goal

Roadmap step 8: a pass with VoiceOver, signing and notarization, and the takeovers only the bundle can
make, tried from it.

## Implementation

**Accessibility, from the tree.** dock2 exposed nothing but its window: VoiceOver could not see a tile.
The dock is now the system Dock's shape — a list of `AXDockItem`s with names, running state, Press and
Show Menu; pressing Files' item through Accessibility opened Files. Search's results were loose text; they
are a list of rows, the selection announced; the field lost its magnifier from the tree, and a first try
at that, returning the field's own children, made the text field `AXUnknown`, so the magnifier is filtered
out of AppKit's children instead. Forms' fields name themselves (Email, Master password).

**The bundle.** `make app` copies the plugins and the Now Playing helper and signs the helper before the
bundle, as notarization wants; `make notarize` submits, staples and zips again for a Developer ID build.
The bundle is 11 MB and verifies.

**"Show in Finder" from the bundle**, run from the terminal with `DOCK2_KEY_STORE=file` so nothing reached
the Keychain: `NSFileViewer` named dock2, and `activateFileViewerSelecting` opened Files at the file. Three
problems, one at a time: LaunchServices brought dock2 to the front, against the product; deactivating gave
the front to no one under cooperative activation, so dock2 yields it to the app that asked; that app's
return took the key window from the panel, since a panel made key while dock2 is active loses it as dock2
resigns — Files now takes the keyboard on resigning. Then Finder stayed in front and ↓ moved Files'
selection. `kill -9` of the bundle gave `NSFileViewer` back, with the Dock and ⌘space.

## Observations

- VoiceOver was never switched on, its speech and keys being the Mac's; the tree is what it reads.
- The dark appearance was seen for search's panel only, through `DOCK2_APPEARANCE=dark`, before the user
  came back to the Mac and on-screen testing stopped.
- No Developer ID is on this Mac: notarization is written, not run.
