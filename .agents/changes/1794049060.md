# Tags that keep to their room

> Change `1794049060` — 2026-11-07

## Goal

Tags overlapped titles and sat awkwardly in lists and details ([the maximal screens](1794039916.md) show every way). A
row's title stopped at a fixed gutter whatever stood at the row's end, and a detail set tags as text attachments with a
space between them, so nothing measured a tag against its neighbours.

## Implementation

**Rows.** `RowView.show` now measures the row's end before placing its words. The order of giving way was the open
decision: the title first, then the tags. Marks take all the words leave and at least half the row (`marksRoom`), so a
short title leaves room for every tag and a long one is cut. Past that, tags stop at what fits and a count stands for the
rest (`PanelMetrics.marks`, pure so that it is tested in Core). A flat half with no regard to the words was tried first and
rejected: Every Tint, which fitted before with room to spare, collapsed to five and "+3" for nothing.

`RowModel` carries accessories rather than an image, since what fits depends on the row's width. The strip is drawn as a
row comes into sight, not for every item as a list renders, and the sniffing that told a tag from an icon by its
proportions is gone, along with the narrow tags and specks of symbols it caused. An accessory naming a tag and an icon now
draws both, and an empty tag draws nothing.

The old gutter stays as a floor: a title in a wide list keeps its place as ↩ comes and goes, and rows that never overflowed
do not move. The title keeps its place on selection too, though the strip hides then, so its truncation does not change
under the user. A hovered row's title now also clears the accessory text, which slides left for the ×.

**Metadata.** Tags stay in the text, which keeps them selectable and inline after a value. The gap is a real space widened
with `.kern`, which leaves a line somewhere to break, carrying only the font so that a link cannot underline it. The gap
between lines is clear space under each pill's image. Paragraph `lineSpacing` was tried first and rejected: under TextKit 2
it adds above the first line too, which pushed tags from their label, and it loosens a wrapped value sharing the paragraph.
`NSTextAttachment` overrides for a width-aware pill were not needed: a fixed 240 pt limit fits the narrowest pane, a preview's
334 pt, and a view's size never depends on its content, so nothing has to be measured at layout.

**Tinting.** A composite image loses `contentTintColor`, so template icons are tinted as they are drawn. `tinted` painted
over a black glyph with `.sourceAtop`, which turned a translucent colour into a dark opaque one, nearly black in the light
appearance. It now does that inside a transparency layer at the colour's alpha. Filling and masking with `.destinationIn`
was tried and rejected: it left a one-pixel line of tint along a symbol's edge.

## Observations

Seen in a Tart VM on macOS 27.2, a debug build, in both appearances. Swift tests, built on the host and run in that VM: 513
pass across Calc, Core, Plugins, System and TOML, and the demo's 6.

Against the build before this change, in the dark appearance, with a threshold of 12 per channel: Every Row's first three
screens, down to its first accessories, differ only by the caret, as does a list beside a preview, and search's results do
not differ at all. Differences that remain: tags and untinted icons, as intended, and a lone icon, which moved by half a
point since `fitted` does not round. Its colour is unchanged. Hover was driven for real on Clipboard History's rows, pinned
and long-titled ones among them: the × takes the pin's place and the title stays where it was.

Not fixed, and out of this change's scope: a selected row in a wide list still draws ↩ in place of its tags. Yellow tags read
poorly in the light appearance. The form, scrubber, grid and button failures in [the maximal change](1794039916.md) stand.
Key presses in quick succession left the selected row off screen in a long list, on the build before this one as well.

In a compact row, accessory text and tags share the same half: with both, often only the count shows. `tahoe-base` was not
tested, nor a real Mac. VoiceOver still reads no tags, which a count now hides from sight as well.
