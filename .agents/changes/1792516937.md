# Organizations, `dock2 plugin`, and a review's findings

> Change `1792516937` — 2026-10-20

## Goal

Three of the plugins' leftovers — Bitwarden's organizations, a plugin installed while dock2 runs joining
search, a command line for installing — and what a read-only review of the newest code found: data loss
in Files, a plugin reaching past its hosts, and an engine that never idled.

## Implementation

**Organizations.** Each organization's key is sealed for the member with RSA-OAEP and opened with the
account's private key, itself sealed with the user key; vectors come from openssl. RSA in the interpreter
costs 218 ms, a hundred items 42 ms, a thousand 422 ms, so opening the vault whole would outrun a
background budget at a few thousand items. It opens a slice an event instead (`vault::Opening`): the
organizations' keys in one, three hundred items in each after, a 100 ms timer between, the list "loading"
meanwhile. A test in the engine opened 3,001 items in 13 events, the longest 228 ms. Organizations' keys
are kept for the run by their sealed form, so a later sync spends no RSA.

**`dock2 plugin`.** `list`, `install`, `dev`, `remove`, sharing Settings' store on the same files. A
running dock2 hears a distributed notification carrying the plugin's id, stops what ran of it — while the
store still knows its tiles — reads the store again, and starts tiles. A notification without the id
would have meant stopping every plugin. `PluginStore` became `@Observable`, which retired Settings'
generation counter and makes Settings show what the terminal did. `dev` polls the module and manifest
twice a second and installs once a change has held for a tick, since a build caught half-written would
fail and count toward switching the plugin off; it asks again only if what the plugin reaches grew, and
runs `log stream` for the plugin's lines. Compiled modules are pruned as builds replace them; installing
over a first-party id is refused, since the bundled copy would silently win.

**The review**, each finding tested before its fix where a test could show it:

- copyfile's callback returned "continue" on errors: copyfile then skips the file, and a move across
  volumes removed the source it never copied; on a data error it retries for good — the old code hung on
  the new test. It now quits on the first error and names the file.
- Replace deleted what it replaced, so ⌘Z lost it. It goes to the Trash once the newcomer is in hand, the
  move keeping where, and undo puts it back; redo puts it aside again. `replaceItemAt` is gone.
- "Already where it is" compared a URL with a trailing slash to one without, so moving within a folder
  asked about a conflict with itself. Copying there now duplicates, as Finder does.
- A failed placement left the hidden partial copy; a batch that failed partway recorded nothing for undo.
- A redirect was followed to any host: a per-task delegate now refuses one outside the allowlist, and the
  redirect itself is the answer — tested against a loopback server. `open` needed no capability at any
  time; permissions say only in answer to an action, now enforced.
- Bitwarden signed out on any failed refresh, offline included, deleting the cached vault; an expired key
  stayed in the Keychain until something ran to lock it.
- The epoch ticker woke a thousand times a second for the life of the app: it now waits on a condition
  while no call runs. Sampled idle, the thread sat in `pthread_cond_wait`, dock2 at two wakeups in five
  seconds.
- Secrets were read from the Keychain on the main thread; an update from Settings left the old code
  running; a plugin's paste could not be concealed; an empty buffer could reach Rust as a null slice.

## Observations

- A move across volumes was tested through the copy it starts with; no second volume was mounted.
- The redirect guard's host check is tested directly; the loopback test can only show the refusal, since
  plain HTTP is never allowed.
- Distributed notifications reach only the user's own session, and the command line and a running dock2
  write the same `plugins.json`: a change made by both at once keeps the later one.
- Bitwarden's organizations are tested against openssl's keys, not an account's.
